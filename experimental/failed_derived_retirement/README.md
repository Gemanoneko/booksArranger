# Failed-derived retirement: isolated contract experiment

Source-only planning/crash-ledger model. No tests/imports executed. No filesystem/native access, disposal call, application/catalog integration, queue reset, installed change or real reclaimed-byte claim.

## Exact purpose

A failed job does not need every invalid generated copy forever. This experiment models a potential earlier route for the two generated members checked.m4b and compatible.m4b, while preserving enrolled source snapshots, existing recovery/originals, exact old attempt/journal/manifest/failure, compact diagnostics and required unique representatives. Names restrict the profile; names or current hashes alone never establish disposal eligibility. Existing published-output working_files logic remains unchanged.

The module deliberately has no apply/delete API. DiagnosticPlan is an immutable fingerprint for review, never deletion authority. HeldScope/HeldArtifact are interfaces for a future trusted app-owned adapter; a JSON safe:true record cannot implement them. Test FakeScope and FakeLease are in-memory illustrations, not native evidence or an authorization mechanism.

## Actual admission required beyond this model

- App admission owns an exclusive catalog/worker boundary; freeze exact job, old attempt, revision, journal, manifest and failure. Refuse any active attempt, publication intent/output or derived reference from another attempt, recovery or publication. Recheck before and after leases and again before disposition/CAS. A completed/failed UI label is insufficient.
- Hold every ordinary owned ancestor against rename/reparse replacement. Use existing native_io identity domain (FileIdInfo128 or specifically permitted BY_HANDLE_FILE_INFORMATION64 fallback), nonzero volume/file IDs, one link, ordinary file, exact size/time/hash and only the unnamed data stream. Hash and disposition use the same held handle. Ancestry and required protected source/evidence leases remain held through final disposition receipt and closure.
- Authenticate new canonical artifact/evidence enrollment against app-owned durable receipts, including all bound payload fields. Reusing an unrelated receipt digest cannot certify changed data. Producer receipts are accepted only if they genuinely exist. Existing legacy generated pairs do NOT gain historical producer receipts from their names or current hash. A separate new verified-legacy-redundancy enrollment would need actual source containment/rebuildability proof, exact generator/source/manifest binding, full native/current-byte observation, diagnostic extraction and explicit unique-evidence preservation. This experiment creates none.
- Verify every protected source snapshot against its enrolled byte provenance; ensure all unique source/recovery dependencies are retained and independent of targets. Current source/target identities cannot overlap. Full source-set digest binds each derived receipt; changing a source invalidates admission.
- Freeze failure/manifest evidence covering every target exact hash, preserve native-held compact diagnostics, retain any designated unique representatives. The enrollment authority must determine that coverage is sufficient; this pure model cannot decide whether real audio/container evidence is unique.
- Match an explicit dry-run plan fingerprint. Native deletion requires a fresh live app-owned adapter and exact current CAS/lease checks; an old serialized DiagnosticPlan can never be applied directly.

Canonical enrollment digests defined here are NEW experiment records, not replacements for existing stored receipt formats. A future adapter must preserve and verify original receipts when enrolling into this domain. No historical producer proof may be invented.

## Crash receipt states

The pure ledger uses existing storage_cleanup vocabulary: verified -> removal_intended -> disposition_set -> removed. It models immutable expected-row/CAS and append-only prior-state/event history. It replays every history event from verified and rejects inconsistent/forged terminal rows. Native intent must be durably committed BEFORE exact-handle disposition; disposition receipt then native close/observed absence precede removed. Real adapter must authenticate these observations, not accept event JSON as authority.

Missing without intent refuses. Missing after intent without disposition receipt becomes absent_after_intent (uncertain, never claimed native disposition proof). Missing after a durable disposition receipt can reconcile removed. An exact still-present identity after intent retains that intent and requires full fresh admission before any retry. Present after disposition/terminal receipt refuses: never delete a replacement name. Commit/CAS failure preserves prior row/history; native operation is never replayed by a broad database retry.

No automatic original/recovery retention change, no conversion retry flag override and no age-based policy are included.
