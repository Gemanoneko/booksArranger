# Books Arranger — local audiobook prototype

In Audiobooks, **Start automatic processing** performs one discovery pass, researches public work identity and queues only candidates that pass every metadata, exact-source/order, encoding and cover check. **Stop automatic processing** saves pending work and pauses audiobook jobs; server restart waits for Start. Uncertain books show Held with a reason while other books continue. **Manual review** remains an optional disclosure for exceptions. **Create audiobook** creates a new M4B; selected ready books can enter a persistent queue with separate pause/resume controls. An interrupted book restarts while validated completed outputs are reused. Eligible selected MP3 originals are removed only after verified conversion and exact source cleanup; verified working copies are then discarded automatically, while original-track recovery copies are kept for 24 hours after successful source cleanup. Errors preserve remaining recovery and source data. Other source formats stay in place, and destination collisions fail without overwriting. The jobs panel shows phase progress and “X converted out of Y approved books”; fully approved unqueued books join the total, while mere discovery does not. The Converted candidate filter uses the same verified output and applicable file-cleanup result. Metadata and source reviews remain independent. Unknown publisher recording completeness is displayed separately from reviewed source coverage and technical output checks; Apple Books device sync remains unchecked.

**View metadata** displays source clues and artwork separately from approved preview values and actual validated output tags. **Open folder** opens a catalog-derived source directory only when clicked; candidates with several source directories offer explicit choices. A created output directory is available only for a validated completed job. Unsupported/unreadable artwork is reported rather than substituted silently.

Audiobook creation requires Windows, Python 3.12 or later, and installed FFmpeg/FFprobe (profile tested with 8.1.1). Encoding uses two audio threads and below-normal priority. Private immutable hashed snapshots, full decoded sample counts, one attached cover hash, Unicode author/title/series tags and optional QuickTime chapter boundaries are validated before handle-bound exclusive publication. Source tags, unknown/private metadata and reviewer provenance remain in the durable job manifest and originals; cross-format copying of every private MP3 tag into MP4 is not claimed. Local output and private staging space are checked, and unsupported destination protection/publication semantics fail closed.

Automatic research fetches anonymous FantLab work/translation records and independent adjacent publisher/journal author-title credits. Filename, embedded metadata and folder clues all retain their provenance. Wikipedia article revisions, language labels and public references are leads, as are search results and the bounded citation index; none alone authorizes a conversion. Manual metadata lookup still prepares unapproved Open Library drafts; optional configured Google Books support remains in its provider module. Network/provider failure preserves manual evidence review and never fabricates verification. No source audio is uploaded. Original-work language and author role require evidence; raw Artist may be the narrator.

The browser's Audiobooks view now offers **Files** and **Book candidates**. Candidates retain every audio member, related companions, source clues and proposed order; folder/Artist tags never establish an approved book identity. For an optional manual exception, save draft metadata before **Approve candidate metadata**. Metadata approval leaves membership, recording completeness and order unverified and does not merge audio. Changes to source evidence or reviewed values invalidate approval through durable candidate revisions.

Status filters apply to the entire selected library before pagination. **Read errors** shows unique unresolved source errors; the shortcut clears the query so every error is reachable. Scan status separately reports checked file outcomes, metadata reused, read failures in this scan and currently unresolved files. Directory failures appear under **Scan issues**. A new discovery pass lists folders/stats files, reuses unchanged healthy metadata and reads only new, changed or previously unreadable files; Resume continues pending work.

Double-click `launch.cmd`, or run `python app.py` in this folder. Requires Python 3.10+ with Tkinter. Optional `ffprobe` on PATH reads audio tags; it is already available on the development machine. No package installation is required.

Open **Books Arranger** from the Windows Start menu. The normal entry targets `launch-web.pyw` through installed Pythonw and opens http://127.0.0.1:5210/ only after readiness; no command window needs managing. Opening it again reuses the verified existing app without starting automatic work. **Restart Books Arranger** is the separate Start-menu action for an idle app: it verifies the replacement process before safely stopping the owned old app, preserves completed records, and leaves automatic work paused. Use the existing Start automatic processing control when you want to continue. Install these two user-level entries with `python install_app_entries.py`; it refuses existing unrelated targets and adds no Desktop shortcut or file association. Developer alternative: `python web_server.py` or `launch-web.cmd`. The app keeps its exclusive loopback port and catalog lease, and health reports the version loaded by that owner. Ordinary user app launch accepts Windows Job membership; it does not change or escape Jobs. Existing ownership, idle, completed-record and readiness checks govern startup and restart. Tool-host persistent launch is not a supported route.

The browser has Start/Stop/Resume, inventory search and pages, evidence details, canonical metadata review, and sorting previews. Library paths cannot be changed through HTTP. Source files and catalog databases are never served as downloads; only protected cached cover images are displayed. Requests use a process-specific token plus host/origin checks. The application is local; optional public metadata queries use HTTPS and audiobook creation uses installed FFmpeg.

Inventory counts and pages refer to source files, including individual chapter tracks and companions; they are not a distinct-book count. Book candidates have their own provisional grouping and independent review gates. A transient browser transport failure shows a separate retrying notice and last-received status. A complete successful current-library poll clears only that notice, preserving review/action feedback and actual read-error counts/details. The notice does not imply that the scanner stopped.

Closing the browser tab leaves the server running. **Stop server** stops scanning safely and shuts down the owned service; Ctrl+C in its terminal also stops it. Scan checkpoints remain available on the next launch. `data/web-instance.json` records the live application's PID, instance ID and URL for identity checks; it contains no request token. Its identity endpoint is `/api/health`.

Select Audiobooks, Podcasts or Ebooks and click **Start scanning**. **Stop scanning** saves completed inventory and pending work. **Resume scanning** continues the saved queue, even after reopening the app. These **Discovery only** scanner controls inventory files without approving or converting them. Automatic audiobook processing is an explicit separate Start action. Subsequent completed scans discover arrivals and reuse metadata when size and modification time match. Files changed by the same size while retaining the exact modification timestamp require a future stronger integrity pass; this prototype does not hash entire audio libraries.

The sources are `Z:\Audiobooks`, `Z:\Audiobooks\Podcasts`, and `Y:\Books\Books`. Audiobook scans exclude the podcast subtree. `Z:\Audiobooks\Unsorted` is included and marked as arrivals; ebook files are eligible arrivals. Podcast episodes remain separate files. Companion images/transcripts and unsupported formats are inventoried without rewriting them.

Select a row to view existing metadata, its confidence and the proposed destination. Missing original-language/canonical-author evidence produces **Needs review**, never a fabricated translated title. Canonical review stores verified choices locally without retagging sources. Creation requires independent exact-source and order evidence; automatic processing must pass those gates without a mandatory human form. Changed evidence invalidates approval. Actual device compatibility remains to be checked with a validated output.

Application state is in the gitignored `data/inventory.sqlite3`, private cover cache and audio staging. Explicit audiobook creation adds a validated new M4B under its reviewed library destination. Eligible MP3 source removal requires full output/source checks and temporary verified recovery. Once successful source cleanup is durable, owned conversion leftovers are discarded immediately and recovery copies expire after the unchanged24-hour retention period. Completed outputs and compact provenance remain. Empty old source folders are checked only from exact retired-source provenance. Automatic folder removal is safely unavailable on named-stream or uncertain filesystems; the actual Z: library is such a drive, so its folders remain intact and the UI reports that limitation. Failed/interrupted work is preserved; recovery/restore is unavailable after confirmed purge. No podcast feed download or audio playback occurs. Ebooks and podcasts remain inventory/preview flows.

If a root is unavailable, saved results remain visible and Resume retries after reconnection. Missing files are marked only after a complete error-free traversal. Symlinks and Windows junctions are skipped. Stop takes effect between entries/reads; a slow network directory read may still need to return first. Audio probes have a 15-second timeout. Unexpected exit leaves running tasks available for retry.

Run meaningful checks with `python -m unittest discover -s tests -v`. Test sources are created in temporary directories. Importing `app.py` does not open a window.

For fixture roots or a second catalog: `python app.py --roots-json scratch/roots.json --database scratch/pilot.sqlite3`. A roots JSON must contain exactly `Audiobooks`, `Podcasts`, `Ebooks`; never point the catalog database at a library source folder.

The web equivalent uses `python web_server.py --roots-json scratch/roots.json --database scratch/pilot.sqlite3` and the same strict port. HTTP safety, exclusive ownership and control-flow fixture checks are included in the unittest command above.

With Node.js available, `node tests/test_browser.js` exercises the actual frontend's unsaved-edit/source-refresh/stale-save flow without opening a window. Node is only used for that check; the application itself requires Python.

Audiobook reviews have an explicit **Short-story collection by multiple authors** checkbox. Only confirmed collections use `Z:\Audiobooks\Сборники`, with a series folder inside it when present (for example `Сборники\Пять Вечеров`). The ordinary author folder and root-level multi-author series controls retain their values while temporarily disabled for an anthology. Ebooks, podcasts, single-author collections and multi-author novel series retain their existing routing. Unknown identities/classifications require review; the scanner never guesses an anthology from its tags.

**Author for Artist tag** stores a verified author credit separately from the surname-first folder name. **Reader / narrator (for comments)** stores the verified reader separately. Embedded Artist/AlbumArtist remain unverified role clues and never automatically populate these fields. The future tag preview credits Artist to the saved author; older reviewed author-folder identity is an explicitly labelled fallback. It preserves the original comment values and appends the reviewed narrator once. Raw tags and source files remain untouched. These optional review JSON fields default to false/empty for older catalog records; no database migration or rescan is required.


`node tests/test_connection.js` exercises the actual polling script through transport failure/recovery, stale-library and incomplete refresh responses, preserving review/read-error feedback and old-HTML compatibility. It also verifies explicit file/task units and intentional shutdown behavior.


Recovery copies of removed original tracks are deleted as soon as the audiobook is verified. A selected book's Delete recovery copies button deletes them by hand when verification keeps them. Finished M4Bs remain untouched. Failed or uncertain sets are preserved for attention. Verified encoding working files are cleaned immediately.

Automatic public response storage is bounded: up to100 URL-deduplicated responses, each at most2MiB, with7-day validity and expiry at public-client startup/next read. Compact candidate decisions, evidence URL/hash/retrieval time/credit excerpt and restart checkpoints persist in the catalog. No source audio is uploaded, no paid connector is required, and no Open Library dump import is included. Missing primary evidence, translation/author ordering, reliable source tracks or verified public/embedded cover correspondence keeps a candidate Held. Complex names, series and many recordings therefore remain outside this first conservative pilot.
