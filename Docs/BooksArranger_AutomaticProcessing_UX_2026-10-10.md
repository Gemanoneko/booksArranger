# Books Arranger — automatic discovery, metadata and conversion

Date: 2026-10-10. Judy UX specification. EXTEND Books Arranger v0.8.0. Scope: browser controls/status, candidate inspection and the authoritative backend facts needed to present automatic work. Preserve existing validated grouping and approved/completed book identities while correcting unreliable folder-only grouping that combines unrelated MP3s. Preserve validated conversion, chapters, source cleanup, recovery retention, scanner checkpoints, library separation and output safeguards. No Comics changes. This spec supersedes earlier requirements for manual review/approve/create as the normal audiobook flow; those remain optional tools.

Sergei authorized automatic metadata research using public sources and conversion of confidently matched books. An uncertain candidate stays held automatically; the user does not have to approve it to let other books proceed. Search confidence alone does not certify the exact recording, intended source set, playback order, usable cover, encoding eligibility or destination. Ender owns those gates and transport/API design. Do not display automation as delivered until its backend executes discovery, research, confidence approval, queueing and conversion.

## Controls and truthful scope

In the existing first control panel, immediately below Library/root and before discovery status, add an Audiobooks-only toolbar: **Start automatic processing** (primary) and **Stop automatic processing** (quiet). Use existing buttons, 10px wrapping gap and at least 32px height/24×24 CSS-pixel target. Keep Library visible; the scope is Audiobooks only. Starting requires one action and never opens a per-book approval dialog. Hide this toolbar for Podcasts/Ebooks; do not extend automation to them.

Start tooltip/help: **Discover audiobooks, research public metadata, and convert confident matches. Uncertain books stay held.** Stop tooltip/help: **Stop research and pause audiobook jobs. Save pending work; finished books stay in place.** Associate both controls with the persistent help below. During a start request disable duplicate submission, show **Starting automatic processing…**, and wait for server acknowledgement. Do not show Running from a button click alone. Start is disabled while the acknowledged run is working/stopping or disconnected; Stop is enabled only when the backend can stop that run.

The existing scan-only controls remain a quiet secondary row labelled **Discovery only**, with existing scanner semantics; they never start conversion. Disable conflicting discovery actions while automation owns that scanner. Keep the existing separate job Pause/Resume controls for interrupted/manual jobs, with their current behavior. During an automatic run, their state and automation status must stay coherent: a paused encoder is never shown as actively converting. Do not add a second scheduler or pretend a scan completion is an automatic-run completion.

Adjacent persistent notice: **Verified audiobooks replace their included originals. Recovery copies expire 24 hours after source cleanup completes, while the app is running.** This applies only to jobs with the existing cleanup-enabled policy; retained-source historical jobs keep their own accurate notice. No change to the 24-hour deadline, automatic/manual recovery deletion or recovery safeguards.

## Status in existing panels

Use one compact automatic status block in the first panel, without a new tab/modal. Show independent facts in normal document flow:

- **Automatic processing: [state]** — Idle, Running, Stopping, Paused, Completed, or Needs attention, using acknowledged lifecycle state.
- **Discovery: [actual scanner state]** — retain existing files checked, pending tasks, read errors and current path facts. Scanner idle does not imply research/conversion idle.
- **Metadata research: [R] researching · [W] waiting · [H] held** — distinct current candidate IDs, not files, HTTP requests, provider hits or historical attempts. Show **Current research: [title] — [source/stage]** only for a backend-active candidate; if more than one is active, add **and [N] more** rather than imply serial execution.

Waiting means a retryable external wait, with concrete text such as **Waiting for [source]; retry at [local time]**. A public source failure is **[source] unavailable; checking other sources** only if alternatives really run. Otherwise show the actual wait/held reason. Missing telemetry reads **Research status unavailable**, never fabricated zeros. Source read errors, public-source waits, held matches and converter failures remain separate facts.

When every discoverable candidate in the run has reached a terminal result and no research/queued/conversion/cleanup work remains, use **Automatic pass complete — [X] converted · [H] held**. With held books, do not say all books converted. Each Start begins one discovery pass, or continues a saved interrupted pass. Do not show monitoring or promise unattended new-arrival checks. A single held book does not mark the entire run Needs attention while other eligible work continues.

Keep the existing Audiobook jobs panel for actual queued/current conversion, exact phase labels, phase-scoped bar, cleanup and recovery facts. Public research does not reuse the encoder percentage. Lead its existing status line with **[X] converted out of [Y] approved books**. Retain **No book currently processing** when there is no current conversion, even while discovery/research continue. An idle queue with X below Y is not all approved books converted.

Y includes distinct current-revision candidates with all authoritative approval requirements satisfied, whether approved automatically or manually. Include approved-ready, queued, running and valid completed candidates. Discovery alone, metadata proposals, held candidates, partial approval and stale approval never enter Y. The denominator can grow during a run. Help: **The approved total grows as more books pass the checks.** X remains the same authoritative distinct Converted set used by the existing Converted filter. X requires verified output and cleanup required by its frozen job policy. Retained 24-hour recovery copies do not withhold Converted or trigger re-encoding; separate best-effort empty-folder housekeeping does not withhold it either. Historical cleanup-disabled completion stays eligible without new source deletion. Return X/Y from one coherent snapshot; retries/polls never double count. Invalid counts use **Approved book progress unavailable**.

## Candidates and held reasons

Preserve existing candidate table columns; use its status cell for **Researching**, **Waiting for source**, **Held — [short reason]**, **Approved automatically**, **Queued**, **Converting**, and existing verified completion/attention states. Never show a percentage confidence badge as sufficient approval. Show canonical title only when established; otherwise retain a labelled title clue. Add **Held** to the existing candidate Status select; it filters distinct current candidates across the library before pagination and resets to page one like other filters. Tooltip: **Show books that automatic processing could not safely approve.** Preserve Converted and other existing filter semantics.

Selecting a candidate opens its existing inspector, led by **Automatic result**, its authoritative state, all actionable held reasons, last attempt time and evidence source links. Present verified canonical metadata, author/reader roles, cover, included-source order, output destination and accepted evidence using existing inspector/table/disclosure styles. Label approval provenance **Approved automatically** or **Approved manually** as recorded, never infer it from fields being nonempty. Research evidence links are keyboard reachable and identify the actual public source. No credential/connect-account control or paid-service invitation.

Use specific held copy, for example: **Book identity uncertain**; **Sources disagree on the title or author**; **Original work language unverified**; **Series position uncertain**; **Mixed recordings in this group**; **Source membership uncertain**; **Playback order uncertain**; **Cover not verified**; **Source files changed**; **Audio format needs an encoding decision**; **Destination already exists**; **Manual draft retained**. Show only reasons reported by the applicable gate, with a concise factual explanation in the inspector. Default help: **Held books stay out of the conversion queue. Other confident books continue.** Do not say review/approval is required to run the automatic pipeline or imply a held book will retry forever. Show actual next retry when one is scheduled; otherwise no retry promise.

Keep the existing metadata form, track review and per-book approve/create actions available inside one collapsed **Manual review** disclosure, after automatic/evidence inspection. Disclosure tooltip: **Inspect or edit this book manually. Automatic processing does not require this step.** Created-output/recovery facts remain outside that disclosure. Opening the disclosure alone does not change approval or queue state. The backend/UI must preserve an active manual draft and hold that affected candidate rather than replace its edits silently; other candidates continue. Polling never overwrites unsaved form values or moves focus. This disclosure adds no new editing capability.

## Stop, restart and connection contract

Stopping must persist pending discovery/research/queue state, prevent new automatic approvals/queue admissions, and acknowledge only after its actual safe-stop contract has completed. Display **Stopping automatic processing — [actual pending phase]** while that occurs. Finished outputs and held/evidence records remain visible. Do not imply originals are restored or recovery expiry is paused by Stop. Stop requests the existing owned encoder pause and stops original cleanup at its safe per-file checkpoint. In-flight bounded fetch/hash/checkpoint work may finish first. Already queued books remain pending; finished published outputs remain. Show **Paused — pending work saved** after acknowledgement. Start resumes the saved discovery/research checkpoint and queued work; after a finished pass it begins one fresh discovery pass. Start tooltip in the paused state: **Continue the saved discovery, metadata research and queued audiobook jobs.**

Closing the tab leaves the server running: retain that fact in the footer. Server stop/restart and interrupted-job continuation must reflect the existing persisted worker contract. Server restart marks the automatic pass Paused and awaits Start; it does not start discovery or encoding. Show **Paused after server restart — start to continue saved work** when that receipt applies. Static help: **One discovery pass per Start. Stop saves pending work; after server restart, Start continues it.** Reconnect/page load merely displays acknowledged state; it never starts work. Connection failure keeps last-confirmed facts marked stale, disables submissions and reads **Connection interrupted; automatic processing may still be running. Retrying…**. Do not change acknowledged state to Stopped from a failed poll.

## Public-source cooldown wording clarification — 2026-10-10

This narrow clarification supersedes the earlier example **Waiting for [source]; retry at [local time]** and any **Next retry** inspector label for the current automatic public-source controller. No unattended source-retry scheduler exists. The controller saves waiting candidate IDs, lets other eligible research, queued audiobook jobs and cleanup drain, then acknowledges **Paused**. Explicit **Start automatic processing** resumes saved research after its backend cooldown. Confident per-book approval and queue admission remain automatic; no manual review step is required.

Approved exact copy:

- Candidate/inspector cooldown line: **Retry available after [time]; Start to continue**. Use the authoritative backend cooldown time, formatted in local date/time with timezone. This is availability, not a scheduled action.
- If the inspector retains a separate fact label, replace **Next retry** with **Retry available after** and show that same authoritative time. Put **Start to continue** beside/below it; do not show a duplicate full cooldown sentence.
- Acknowledged automatic **Paused** source-wait reason: **Waiting for public sources; Start retries saved work after cooldown**.

Keep actual Running/research/conversion/cleanup state while other work drains; an unavailable source alone does not prematurely present the whole pass as Paused or Completed. Waiting candidates remain distinct from confidence-held candidates and stay outside approval/queue counts until their complete checks pass. Missing cooldown telemetry must not invent a time: use **Waiting for public sources; retry time unavailable** and the actual backend Start eligibility. Do not promise automatic retries when the cooldown passes.

No new control, layout, behavior or retention policy. Consumer checks are limited to automatic status/wait-reason rendering, candidate/inspector cooldown text and any copy reproducing **Next retry** or **retry at** for this controller. ## Interrupted metadata research copy — 2026-10-11

Scope: existing automatic **Needs attention** state, run reason, candidate status and readable details only. An unexpected program exception is distinct from an uncertain match, cover issue or public-source cooldown. Do not present a failed, inactive candidate as **Researching**, approve it, blame the user, or invent a historical exception cause. Existing verified completion, held-match and cooldown copy remain unchanged.

Approved wording for an acknowledged program failure:

- Run reason: **An app error stopped automatic processing while researching [book]. Source files for this book were preserved.** Bind [book] to the affected persisted candidate title/clue; preserve its labelled clue semantics. The preservation sentence applies to this research candidate only and requires backend confirmation; it does not describe other books' conversion/cleanup state.
- Candidate status: **Needs attention — metadata research failed**. Research/current-book counters and active labels must reflect the nonactive checkpoint.
- Separate action help, only when Start safely retries that candidate and continues its saved pass: **Start automatic processing to retry this book and continue saved work.** If Start only continues other work, use **Start automatic processing to continue saved work.** If neither action is available, omit these promises and show the actual existing disabled-action reason. No new action/control or mandatory manual review.

If the existing details surface can display bounded sanitized diagnostics, label the readable value **Failure details**. Show only the recorded factual error, rendered as text; no raw traceback, credential/session data or invented cause. An absent historical diagnostic may read **Failure details were not recorded.** Do not turn a normal uncertain-match replay into evidence for what caused the earlier failure. A diagnostic is supplementary: the main reason names the failure and affected book without exposing internal filenames, roles or code references.

Use the existing polite status/error presentation and focus behavior; no new panel, layout or state category. Check the literal copy consumers in run reason, candidate/inspector status and existing details rendering. Safe retry help requires an authoritative eligible checkpoint; page reconnect alone never retries. Doc-only repair, no library/runtime/code/Git changes or probes; owned disposable output: none. ## Automatic eligible source retries — 2026-10-11

This narrow status-copy addendum supersedes **Public-source cooldown wording clarification — 2026-10-10** only for an acknowledged active run with automatic retry enabled. The approved controller now retries eligible saved research unattended. Explicit Stop, server restart, confidence gates, held books and unexpected-error behavior remain unchanged. No new panel, control, layout or provider-policy choice.

Ender field receipt: automatic state remains **Running**, phase **waiting**, current candidate is null while the controller is armed. **automatic_retry_enabled** is true only for an authorized active run. Top-level **next_retry_at** is the authoritative earliest scheduled retry check (UTC epoch); per-candidate **result.wait.kind** distinguishes **app_limit**, **source_pause**, **source_unavailable**, and candidate **retry_at** marks eligibility. Eligible other books and queued jobs/cleanup run before the interruptible wait. Explicit Stop becomes Paused and disables armed retries; restart becomes Paused with **restart_paused** true and no autostart. Waiting retains Stop eligibility and disables Start.

Approved existing status/time copy:

- Running + waiting + automatic retry enabled: **Waiting for metadata sources; saved research retries automatically.** Keep **Automatic processing: Running**. Do not present the waiting run as Paused, Completed, Needs attention or actively researching a named current book.
- Existing top-level retry-time fact: **Next automatic retry check: [time]**. Use next_retry_at; this is the earliest wake to attempt eligible work, not a promise every waiting book starts or succeeds at that time. If missing/invalid, use **Automatic retry time unavailable**; do not invent a timestamp.
- Existing candidate/inspector retry fact: **Retry available after [time]**, from that candidate's retry_at. While automatic retry is enabled, omit **Start to continue**. Candidate eligibility and whole-run next check may differ; never substitute one timestamp for the other.
- Per-candidate wait reason, only from the matching recorded kind: app_limit → **App request limit reached for [source]**; source_pause → **[source] requested a pause**; source_unavailable → **[source] unavailable**. Use the recorded source label; if absent, use **App metadata request limit reached**, **Metadata source requested a pause**, or **Metadata source unavailable**, respectively. A mixed/global summary uses the generic Running-wait copy above.

Do not call an app-imposed request limit provider throttling, a provider quota or a provider-requested pause. An expired source cooldown is not a current wait reason. Preserve the actual wait cause and earliest eligibility from the backend; UI does not calculate a maximum across source cooldowns. Routine short spacing remains actual research, not a whole-pass pause. Candidate **Waiting for source** remains separate from confidence-held books and approvals.

For explicit Stop, keep **Paused — pending work saved** and Start-to-continue help. For restart, keep **Paused after server restart — start to continue saved work**. Show paused candidate eligibility as **Retry available after [time]; Start to continue** only when applicable. Never show automatic-retry copy or trigger a retry in these paused states. Unexpected program failures retain the existing **Needs attention** and interrupted-research copy; source waits do not become program-error messages. Confident per-book approval requires no manual review.

Format times in local date/time with timezone, retain polite status/focus behavior and existing count semantics.
