## Filters first

Keep the search toolbar in the inventory panel. Order: existing View selector when candidates are implemented, **Path contains** search, **Status** select, Search, **Clear filters**, Previous, Next and result range. Controls wrap in normal document flow, with an 8px minimum gap; at 700 CSS pixels search can occupy a full row and the other controls wrap beneath it. Retain existing control dimensions, default dark tokens and visible focus. No floating toolbar or overlay on rows.

For Files, the Status select offers **All files**, **Read errors**, **Needs metadata review**, **Preview available**, and **No longer found** only where the backend has those factual states. Read errors means a current unresolved file read/probe error, not missing canonical author/title and not a failed browser request. A file can be errored even if it retains an older metadata snapshot: the error filter must include it. No longer found means a cataloged path verified absent during a completed accessible scan; stopped scans and offline roots cannot establish it. Arrival and Type remain table columns; do not introduce unrelated filter dimensions in this milestone.

For Book candidates, Status uses **All candidates**, **Needs review**, **Metadata approved**, **Source read errors**, and **Candidate changed** when those states exist. Source read errors includes candidates with any unresolved member error. Approval filtering does not imply merge readiness. Keep a separate selected filter value for each view; switching views or libraries resets to the first page. Filter state persists across polling, but it need not become a saved preference.

Every search/filter is applied to the entire selected library/view before pagination, not the first displayed 100 records. Result text: **Showing 1–22 of 22 files · Read errors**, or **No files match these filters.** Library counters retain their library-wide meaning and do not become filtered counts. A status change applies the current search text and resets the page; Clear filters empties search, selects All and resets the page. Search and pagination must not start/restart scanning or discard unsaved review fields. Keep a selected detail record stable while its table row is temporarily filtered out.

Add a compact **Read errors · N** button beside the result controls when the selected library has unresolved errors. It sets Status to Read errors, clears the path query so all errors can be inspected, and resets pagination. Explain this in its tooltip: **Show all files with unresolved read errors in this library.** If already active, do not act as a toggle that hides errors. Use the existing dark warning/error colors plus the textual label; color alone conveys no state. Keep zero-error shortcut hidden, with its space reclaimed in normal flow. The ordinary status select still offers Read errors at zero.

Tooltips and programmatic accessible help ship with every new control: Status **Filter the saved results in this library.** Clear filters **Show all saved results and return to the first page.** View retains its committed tooltip. Counts/ranges use polite status announcements; avoid announcing the full row table on every poll.

## Error inspection

Errored rows show **Read error** in text and a concise reason beside their status. Selecting a row opens the existing details panel with a new **Read error** section above tag evidence: full affected path, last failed read time when recorded, the specific error, and available next action. Long paths and errors wrap; preserved raw metadata remains visibly labelled **Saved metadata snapshot** when it comes from an earlier successful read. Do not relabel every read failure as corruption or tell the user to delete/reacquire a file without diagnostic evidence.

For a file changing during probing, use **The file changed while its metadata was being read. Let copying finish, then start scanning to retry it.** For a zero-byte audio file, use **This audio file is empty. Replace it with a complete copy, then start scanning.** Unknown errors keep their concrete reader message and **Start scanning to retry unreadable files.** Ender owns which diagnostic facts are reliably established; if they are absent, show the actual failure without speculative explanation. No Retry/Delete/Open-folder control is added in this first filter milestone.

## Incremental scan and counter semantics

Retain **Start scanning** with help: **Check for new or changed files and retry unreadable files. Reuse saved metadata for unchanged readable files.** Add a persistent short helper below scan controls: **Scanning checks folders for arrivals. Unchanged readable files reuse saved metadata; new, changed and unreadable files are read.** This describes the required/current incremental behavior without promising that discovery can skip directory traversal or that failed files are healthy. “Missing files” must never conflate uncataloged arrivals with catalog paths that are absent on disk.

Stop/Resume continues the saved pending scan, while Start begins a fresh discovery pass. Explain Resume with **Continue saved pending work without starting a new discovery pass.** Preserve current Stop semantics and any slow-read stopping notice. Do not introduce automatic scanning or a full-rescan option in this milestone.

Show distinct facts, each with an explicit scope: **Files cataloged** (saved file records), **Files checked this scan** (define consistently in Ender's implementation), **Metadata reused this scan**, **Pending tasks**, **Read failures this scan**, and **Files with read errors** (unique currently unresolved cataloged files). The last is the filterable count; directory/task failures that lack a catalog record must be separately inspectable in a small **Scan issues** disclosure containing affected directory/path and reason. Do not force those failures into a fake file row. If the backend cannot supply a counter accurately, omit that counter until it can; never infer it by subtracting incompatible totals.

Read failures this scan is a run outcome count, not a corruption total or historical attempt tally. Include affected paths and outcomes once per completed task outcome according to the backend contract; repeated internal attempts must not silently inflate the user-facing number. Source read errors remain catalog facts across runs until a successful read resolves them. Preserve the scan completion message with unresolved errors; success must not remove a file's error merely because directory discovery completed. Browser connection notices remain separate and follow the committed connection-recovery behavior.
