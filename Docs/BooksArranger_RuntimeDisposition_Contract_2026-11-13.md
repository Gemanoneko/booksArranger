## Module/API and ownership

Operator owns new `runtime_file_disposition.py` and its tests. Core owns `native_io.py`, actual catalog-owner registry/entry integrations, finite-helper capability integrations and QA/build context setup. Existing finalizer/lifecycle metadata remains its own durable authority; there is no raw boolean bypass.

`DispositionContext(control_root, *, scopes, owner_handle, owner_identity, owner_path, owner_kind, catalog_identity=None)` retains an explicit ordinary local journal root and actual supplied native ownership lease. Context validates native owner identity/unique file and native sharing exclusion on every action. `owner_kind` is catalog or support; support is an explicitly owned build/QA/helper operation, not an environment-selected fallback. `scopes` bounds eligible operation paths. Control root must be outside each selected disposal target; never use personal/default/C fallback paths. Source catalog root is `database.parent / 'file-disposition-ledger'`, enrolled under the actual catalog owner before business workers/transactions. A missing new catalog defers enrollment until its base schema is created/committed. Support scopes/root are supplied only by their reviewed owner entrypoint.

`prepare_disposition(held_file, context) -> PreparedDisposition` preserves the caller's current read/delete handle and ancestry. It opens only a sharing-compatible READ_CONTROL/WRITE_DAC/READ_ATTRIBUTES security handle (share read/write/delete, including an already-writable producer cleanup handle) to that SAME file. The ORIGINAL retained handle and applied ACL enforce exclusion; the security handle grants no extra data-write access. It compares actual native identity, then durably creates intent before any ACL change, hashes via the existing held handle and verifies streams before/after fencing. Never close the original early merely to open another handle, and never fall back to raw deletion.

`PreparedDisposition.authorize(held_file)` verifies the exact live native handle/identity/hash, pinned intended/applied fence and stream inventory immediately before native SetDisposition. Core's private native primitive accepts this live capability; callers cannot pass a bypass boolean. Finite lifecycle/source-finalizer adapters issue equivalent capabilities only from their pinned durable intent plus actual held write/ADS fence.

`PreparedDisposition.mark_pending()` durably records successful native SetDisposition, without closing the caller's handle. The in-memory phase changes to disposition-success IMMEDIATELY after the kernel call and BEFORE attempting to persist its pending receipt, so a pending-receipt fsync failure cannot enter pre-disposition rollback.

`PreparedDisposition.close()` is invoked from `VerifiedFile.__exit__`; it owns/executes the actual native CloseHandle of the EXACT original handle ticket, verifies the return, then closes the retained security handle and records closed removal only after positive namespace absence. No arbitrary caller boolean certifies closure. An already-null/replaced/unknown handle is held rather than treated as proved closed. Existing finite-helper raw close paths must retain their independent exact native close proof/capability recipe. This preserves mark-pending/close-later semantics and surrounding CAS.

`PreparedDisposition.abort(error)` is phase-aware. ONLY before successful SetDisposition (or after separately proved native cancellation) may it restore this operation's exact original/own planned/DELETE-relaxed ACL. After disposition success it MUST retain the write/ADS fence through safe closure, even if journal persistence subsequently fails; never expose writable delete-pending originals. Foreign changed security is never overwritten, and incomplete closure remains a truthful held outcome.

`recover(context) -> {restored, held, removed}` runs under actual ownership before writable recovery/retention/conversion constructors. It restores a remaining exact same native file/bytes only when current security equals already-original or the durably persisted planned/DELETE-relaxed ACL. It never treats intent/mark followed by missing pathname as closed deletion proof. A reused pathname is held and untouched. Independent closed proof is byte-pinned, exact native original identity and full SHA-bound. Unknown/malformed records remain held. No metadata restoration grants producer/boot/closure or deletion authority.

## Durable external file journal

One CREATE_NEW immutable intent per operation, followed by separate CREATE_NEW fenced/pending/closed/held records. Intent schema `books-runtime-file-disposition-v1` contains operation UUID, owner kind/path/native identity, optional catalog identity, exact target path/native facts/full SHA, original security descriptor and precomputed intended write-fence ACL. Every later record binds intent SHA and operation UUID. The context root marker binds actual catalog/support ownership and root native ancestry. All records are bounded ordinary single-stream unique files. Raw security descriptors are bounded/self-relative/structurally validated before native APIs.

The intended ACL is computed from captured original security before intent publication. Immediately before SetSecurityInfo, original security must still match. Actual applied protected DACL must equal the persisted intended ACL; only the known conversion of INHERITED_ACE flags to explicit protected ACEs is included in the computed transition. Masks, SIDs, other flags and order remain exact. Recovery permits only that exact planned or its exact DELETE-only relaxation, with owner/group/protection unchanged. Never blindly restore solely because native ID matches.
