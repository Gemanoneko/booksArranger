## Essential code-review conditions

1. **Bind the existing artifact and reviews.** Derive the input from the recorded completed job, verify its exact hash/size/parent identity under the accepted file/directory protections, and bind the40 source members/order/content hashes, canonical metadata/cover and relevant review revision to the repair. Recheck the input/source/review identity immediately before publication. No arbitrary client path/executable or arbitrary existing M4B can become a repair source. Derive the reviewed new destination from the verified original artifact; it is neither an in-place edit nor a source overwrite.

2. **Do not blindly reuse the creation guard.** Existing `MergeService._guard()` calls `build_manifest`; that path rejects a now-occupied canonical destination and uses the current encoder profile, whereas the pilot is a historical completed profile. Repair therefore needs an explicit guard for the recorded completed parent and exact current source/review evidence. It must not globally disable collisions or source guards to make the completed parent acceptable. A profile difference alone must not force AAC re-encoding.

3. **Prove audio/presentation identity.** Use stream copy rather than an audio encoder, and retain codec/extradata, sample rate/channels and the exact compressed AAC packet payloads. Duration alone does not prove preservation: timestamps, start position, encoder delay/skip-discard padding and MP4 edit-list presentation can change during remux. Compare packet/extradata identity and exact decoded PCM frame count/hash between protected original and repaired outputs, or an equivalently demonstrated presentation check. Harmless timestamp-origin normalization may be accepted only when unchanged playback presentation is established. Cover bytes and canonical/additional metadata remain validated. No altered compressed or decoded audio may be published as a lossless marker-only correction.

4. **Chapter boundaries and escaping.** Build starts/ends from the supplied ordered integer PCM counts, with an explicit timebase/rounding rule and bounded marker error. Require nonnegative, increasing contiguous boundaries within the validated presentation duration and exactly40 markers; verify output names and start/end values against the plan. Escape FFmetadata backslashes, separators and newlines using the existing bounded escaping mechanism. Labels lacking source titles remain TrackNN, not fictitious title metadata. Do not trim intros/ends, infer missing book material or splice AAC at the chapter markers.

5. **Protect private staging and final publication.** Reuse owned UUID staging, accepted deny-write/delete directory/file guards, restricted file protocols, validated argument arrays and owned process cancellation. Validate the private remux before destination copying; the destination temporary must be created exclusively and its exact held file identity/hash/size checked before same-parent no-replace publication. Reject a pre-existing corrected destination, drift or unsupported platform behavior; no overwrite, suffix loop or in-place AAC tag operation. Keep the original pilot and40 MP3s unchanged.

6. **Keep durable corrected-artifact provenance.** Before rename, persist repair intent with repair UUID, parent completed-job/artifact hash, boundary-evidence hash, exact new destination and validated expected hash/size/chapters. Commit an append-only corrected artifact record after publication; preserve the parent's original record/evidence rather than rewriting its history to claim it always had chapters. Recovery may adopt only the expected matching repaired artifact, never an unrelated file at that name, and must not rerun or overwrite a completed correction. Register the new output so scanning does not regroup it as an unsorted source book. Source/evidence revisions remain invalidatable; unfinished temporaries remain owned recovery artifacts.
