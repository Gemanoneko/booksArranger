## 1. Phase contract: viable amendment, not current implementation

**Accept the PRE/POST split as a proposed new contract, with the following mandatory corrections.** PreToolUse cannot prove the future result of the command it admits. It must not run canonical QA and subsequently permit that command to run again. Existing `{status,stdout,stderr}` remains the hook transport; status zero is not native closure evidence or a blanket permission override.

* PRE recognizes and validates only one fixed **protected watchdog executable** invocation, pinned registration/context and exact tool envelope. Direct `launch-books-qa.mjs` execution stays denied: that entry imports Koffi on the explicit assumption that its native parent already froze the bootstrap. Its caller-supplied deadline is not proof of that parent. Delete “direct protected entry” from the proposed allow surface.
* Raw canonical checker and Books-owned npm/package operations must be denied before the opaque fallback; current `isBooksOperation` does not recognize them, so their required denial is not established by this branch. Specify a finite Books-command classifier with executable-position parsing, reviewed Books cwd/script identity and conservative rejection of unsupported wrappers. Ordinary search/echo arguments containing these names remain data. Preserve the original owned QuickLaunch priority and every non-Books fallback byte and behavior. No general shell interpreter or new general executor.
* Replace the unavailable Git Bash envelope with an explicitly reviewed, fixed default-PowerShell literal command contract for the observed tool route. Do not invent a tool timeout field or claim `yield_time_ms` bounds execution. The watchdog supplies its own stated 600000ms work/closure bound; its trusted loader/startup base remains explicit. Unknown shell/envelope/extra tokens deny.
* PRE validates protected launch bytes/ACL policy and the intended registry/context. It does not lend short-lived hook handles to a later invocation. The actual watchdog must independently reacquire/freeze every required mutable input, validate policy/context/runtime and establish its private Job/deadline before releasing its **one** QA child. A PRE/runtime race is a runtime refusal, never permission to use a changed input.
* POST is a separate QA-result consumer, not another PreToolUse action. Accept only the actual original tool invocation's terminal result plus the reviewed native watcher's result framing, joined to the exact registry/context/source pins and this invocation. Require exit success, native Job zero, retained-handle waits/checked closes, required input/pipe closure and EOF, bounded output and deadline. Failure, missing terminal observation, copied/replayed result or ambiguity means no accepted QA receipt. No inference from PID absence.

**Concrete missing POST contract:** current C++ final line reports counts/elapsed but no registry/context/invocation join; child output shares the stream. Define a finite native-origin terminal framing and immutable invocation binding, and reject child-emitted/lookalike/duplicate/trailing frames. The direct fixed protected executable and captured original tool result are the trusted producer/observation boundary; a writable JSON file or claimed `closed:true` cannot replace it. Do not silently import engineering-owner-v3: current C++ member retention has neither its image admission nor PID/creation records. Review and test the C++ contract actually selected, including transient-member limitations, separately.

Shortest evidence: pure exact-command/classifier/envelope and host-transport tests; independent review of frozen runtime/result changes; current-source build with actual compiler closure; finite native success, timeout, child/descendant/output/early-failure/checked-close cases; actual original-tool result correlation. Then exact source/harness/runtime/Git closure and sequential canonical receipts. No hook-side QA, unsupported consumed-command semantics or automatic retry is necessary.

## 2. Provisioning: explicit human bootstrap can terminate the trust chain

**STOP the proposed production-native-cap implementation as currently specified.** No admitted primitive presently supplies its held full128/birth/stream/ancestor APIs. Stock PowerShell text checks cannot certify them, and a new writable elevated native helper cannot authenticate its own privileged bootstrap. Requiring that helper to install itself merely repeats the gap.

A finite alternative is an **explicit new trusted-human disabled-bootstrap amendment**. Its trust base is the existing trusted Windows PowerShell 5.1/.NET installation, the already protected Program Files ancestry, a human-controlled privileged quiescent session, and literal reviewed bytes/digests of the exact current-source artifact and complete bounded manifest. It does **not** promise native full128/held-directory proof before the first native verifier exists. This reduced pre-native property must be approved and recorded rather than relabeled as the original backend contract.

The literal creation-only procedure must refuse an existing target, create the fixed leaf protected at birth, copy only the exact bounded closure using no-replace files and same-held source bytes, flush/close/read back and verify exact owner/DACL/bytes/streams/member sets, and leave registration disabled and global hooks untouched. Exclude competing privileged installers/writers for that operation; do not claim protection against an uncooperative administrator. `Directory.CreateDirectory(path,security)` is not atomic absence: trusted-parent plus privileged quiescence is the explicit assumption. Any uncertainty leaves a disabled preserved root. No automatic rollback/delete/adoption.

Before even requesting that human step, the shortest necessary measurements are: read-only installed CLR constructor reflection; in-memory ACL construction/normalization showing actual Synchronize masks; fresh read-only protected-parent eligibility; and a fixed finite birth/copy/readback fault demonstration on an explicitly admitted disposable target under its own reviewed scope. No measurement itself authorizes privileged creation. After the approved human disabled copy, first protected native verification must independently check the complete installed objects/ancestry/ACL/streams/IDs/bytes before any enablement or QA. This first operation also needs a reviewed fixed invocation and observable closure; it is verification only, not a generic installer or canonical QA. If the trusted-human reduced bootstrap is unacceptable, STOP pending an already trusted primitive; do not grow a recursive launcher stack.
