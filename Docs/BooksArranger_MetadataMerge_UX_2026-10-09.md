# Books Arranger: verified metadata and one audiobook per book

Date: 2026-10-09. EXTEND the committed candidate-grouping and anthology/author review interfaces after their incremental implementation. This follow-up adds source matching, explicit review of tracks and metadata, and creation of one M4B per reviewed audiobook. Earlier read-only milestone specs remain historical and unchanged. This is a staged handoff: metadata matching/review first, one-book merge pilot second, then incremental batch processing after validation. Do not display functional merge controls until the corresponding backend is implemented and validated.

## Scope and page flow

Use the existing Audiobooks **Book candidates** view and selected-details panel. Keep Files, Podcasts, Ebooks, scan controls and filters available. Candidate details have three sequential sections in normal document flow: **Metadata**, **Included audio files**, **Audiobook output**. Keep a compact status line above them with independent facts: metadata review, track review and output state. No wizard, automatic page advance, modal stack or separate settings panel. Preserve the default dark tokens, typography, field layout and selected-row behavior.

Metadata lookup, track review and conversion have distinct states. Reading source tags does not verify identity. Approving metadata does not confirm membership or order. Converting audio does not prove output validation or actual iPhone sync. Use **Needs metadata review**, **Tracks need review**, **Ready to create**, **Queued**, **Creating**, **Checking output**, **Audiobook created**, **Output needs attention**, and **Source changed — review required**, with specific blocking reasons adjacent to the relevant section. Show the backend's actual condition; avoid a generic green Approved badge across the entire book.

Podcasts remain individual episodes with preserved podcast metadata and are excluded from grouping/merging. Ebooks remain unconverted. Single existing M4B recordings show **Single audiobook file**; do not queue them for concatenation solely because they are candidates. Retagging or copying an existing M4B requires a separately implemented path, not silent re-encoding.

## Metadata proposals and evidence

At the top of Metadata add **Find metadata**, tooltip **Find possible book identities and metadata sources for this candidate.** It queries one book candidate, not each MP3 chapter. Show **Finding metadata…**, a concrete source wait/failure message, or **No reliable match found. Review the title and author, then try again.** Cached proposals remain readable during source cooldowns. Provider outages/credentials are source availability, not file-read errors. An unreachable source shows **Metadata source unavailable. Review cached evidence or enter verified metadata manually.** Never fabricate verification or require successful network lookup to save manually verified metadata. Identify a genuinely optional credential dependency only when that provider is actually implemented.

Display possible identities as a short list in the Metadata section, ordered by the backend's evidence-based match strength. Each entry shows original title, author, source, original-work language when known, series and position when supported, edition/recording information when available, and relevant mismatch reasons. Show **Original work match; recording unverified** when a print/work record identifies the book but cannot identify this audio recording. Use **Use as proposal**, tooltip **Fill draft metadata from this match. Review the fields before approving.** A source URL link opens its actual public source; its accessible name includes the source/title. Selection updates drafts only, never publishes tags or approves the book.

Do not convert a confidence score into approval, invent a language/series position, copy reader Artist as author, or treat a storefront list position as canonical series numbering. Multiple plausible works, translated titles, conflicting series numbers, author/reader ambiguity and mixed editions remain visible conflicts. Automated lookup may prepare drafts for a batch; unresolved candidates do not advance to creation automatically.

Retain canonical title, original-work language, author-folder, Author for Artist tag, reader/narrator, series/number and anthology fields. For each proposed canonical value show a compact **Source** link or **Manual review** label, with **View evidence** disclosure when several sources or conflicts exist. Evidence includes the supplied value, source URL/record ID, retrieval date, and the accepted value. Add one **Manual evidence** multiline field after canonical fields, tooltip **Record the source and which fields you verified, such as an author page, publisher record or book credits.** It saves a note with the approved revision; a pasted URL alone is not an automatically checked source. Untouched source tags remain inspectable separately. User edits are preserved during polling and lookup completion; new proposals require Use as proposal.

The confirmed language rule concerns the original work: original non-Russian works use English canonical title/author/series, including Russian translations; original Russian works use Russian. Recording/edition language is separate and retained. Author folder uses surname first; Artist uses the verified author credit, never the reader. Preserve the reader in a labelled Narrator comment alongside all additional source comments. Preserve useful metadata from all included tracks in the catalog/recovery record even when the single output format cannot represent every original tag. Do not silently flatten contradictory per-track values into a fictitious book-level value.

Add **Cover** below canonical fields. Show one selected cover thumbnail, source name/link and evidence label **Recording edition**, **Work cover**, or **Local artwork — edition unverified**, according to actual evidence. Use **Use this cover**, tooltip **Select this image as the single cover in the output audiobook.** Alternatives live in a collapsed **Other covers** disclosure. Local embedded/companion artwork can be proposed without treating it as verified edition artwork. A work cover may be accepted explicitly despite an unverified recording edition; it must not establish audio compatibility or identity by itself. Broken/absent images show readable text and keep review pending. No upload/file-picker control in this minimum flow unless separately requested/spec'd.

Retain **Save preview metadata** to save drafts. **Approve candidate metadata** approves the exact accepted field/evidence/cover revision. Required identity is canonical title, author credit, original-work language and resolved series identity/position when applicable; select one usable cover for output. Unknown optional narrator may remain unfilled, with source reader evidence preserved. A blank series must mean a reviewed standalone decision, not an unresolved series conflict. Explain any disabled approval beside it: **Confirm the author**, **Choose a cover**, **Resolve the series position**, or another concrete condition. Approval still leaves tracks pending. Later metadata/cover edits invalidate metadata approval and any readiness derived from it.

## Track membership, order and recording review

Extend the committed Included audio files table with an **Include** checkbox per audio row and **Move up** / **Move down** quiet buttons beside Proposed order. The filename, source number, duration and order evidence remain visible. Tooltip Include: **Include this source file in the output audiobook. Excluded files stay untouched.** Button tooltips include the filename and direction. Controls are native keyboard-operable; reorder is also available without dragging. Disabled first/last movement buttons remain readable. Use a checkbox's full label hit area, minimum 24×24 CSS pixels, with 32px comfortable button height and 8px gap between actions. No row action overlays text or another control.

An excluded row remains in the review table with **Excluded from output**, its source evidence visible and inclusion reversible. Companions remain in their separate disclosure and never receive audio inclusion controls. Never omit zero-numbered introductions, repeated chapter names, unusually short files or duplicate-looking tracks automatically. Inclusion/reordering saves as candidate review data and invalidates track approval. Split/join across candidates is deferred: a candidate mixing books or recordings stays blocked with **These files may belong to different recordings. Correct the source grouping before creating an audiobook.** Do not offer exclusion as an automatic shortcut around unresolved recording identity.

Below the ordered list show total included audio files and summed duration when every included duration is known; otherwise **Total duration incomplete** with the affected files identifiable. Report **Folder scan complete** separately from **Recording complete**. Directory coverage is not proof that a book lacks no chapters. Read failures, missing included files, changed fingerprints, ambiguous ordering or incompatible/mixed recording evidence block creation with concrete reasons.

Add two unchecked review confirmations after the list: **These included files belong to one recording and include the complete book** and **This is the playback order I want**. Tooltips: **Confirm this exact set of files. A completed folder scan alone does not establish book completeness.** and **Confirm the displayed order, including introductions and disc boundaries.** These are review declarations, not an app-certified fact; label saved facts **Completeness confirmed by you** and **Playback order confirmed by you**. Require both for creation in this review-first milestone. Ender independently checks source readability, recording compatibility and revision stability; user confirmation does not bypass a detected conflict. Changes to membership, file fingerprints, relevant source evidence or order reset these confirmations. No inferred completion from contiguous numbers.

## Output review and one-book pilot

Audiobook output shows the exact final path, M4B format, included file count, total duration when established, title, Artist, series/position, reader/comments, selected single cover, and chapter plan. Apply current routing rules: surname-first author folder normally; root cycle for multi-author novel cycles; multiple-author short-story collections in `Z:\Audiobooks\Сборники`, nested by anthology series when provided. Display the complete filename and path before queueing; no abbreviation that hides a collision or different destination. Output paths follow the confirmed naming rules. Library root/Unsorted rules remain unchanged.

The output contract is one Apple Books audiobook file with Unicode metadata and the verified author as Artist. Encoding/profile details are Ender's technical responsibility; expose only **M4B audiobook** and meaningful validation facts, without a settings matrix. Chapter markers are optional: show **Chapters from reviewed tracks** only when one-track/one-chapter boundaries and names are credible and reviewed; otherwise **No chapter markers**. Do not invent chapter names, label every MP3 a chapter, or block a whole book solely because chapter markers cannot be established. If markers are offered, a native checkbox **Add chapters from these tracks** appears with tooltip **Use the reviewed track boundaries and names as audiobook chapter markers.** It defaults off until those boundaries are established; metadata and order review do not enable it silently.

Display the short notice **Creates one new audiobook. Your source files stay in place.** Replace the global read-only-only notice once writes are genuinely implemented with **Scans preserve source files. Audiobook creation writes a new output file.** The read-only copy remains accurate in earlier milestones. Conversion never rewrites the MP3s first or deletes sources. The approved metadata is applied to the newly merged output after source identity/order have been checked; source tags remain evidence/recovery data.

For the first validated conversion path, add **Create audiobook**, tooltip **Create and check one M4B from this reviewed book. Keep the source files.** It is enabled only when metadata and track review are current, all included sources pass checks, destination is valid, and no output collision exists. Clicking queues this exact candidate revision without a second generic confirmation dialog. If a destination exists, show **An audiobook already exists at this path. Review it or choose a different reviewed destination.** Do not overwrite, append a hidden filename suffix, treat it as this app's successful output, or delete it. The minimum collision flow remains blocked until a canonical title/series/path decision resolves it; implementing an explicit alternate-filename field would need a bounded UX addendum.

Show progress in this section: **Queued**, **Creating audio**, **Writing metadata**, **Checking output**, then **Audiobook created** with the final path. Percentage is shown only when the worker has meaningful measured progress; otherwise a stage and processed-time/file count suffice. Never publish an unvalidated partial file at the final path. The output must pass the backend's media/container, duration, metadata, cover and chapter checks before Created. If checks fail, show the failing check and preserve a retryable job; distinguish a failed temporary output from the untouched source files. Do not claim **Works on iPhone** until the user has actually verified iTunes/Apple Books import, search and sync on the intended devices. Show technical verification as **Output checks passed**, with separate **Apple Books sync not checked** until a real pilot has established it.

## Incremental batch queue after the pilot

After the one-book pilot and actual device/import findings have been handled, extend candidate rows with selection checkboxes labelled by title. Add **Queue selected books**, tooltip **Queue the selected reviewed books. Incomplete or changed candidates stay out of the queue.** Select-all applies to the explicitly visible page and is labelled **Select this page**, never silently the whole library. No auto-start on scan completion and no automatic queue of every proposed match. Before the button, show **N selected · R ready · B need review**. Clicking queues only the ready selected revisions and reports which selected candidates were excluded and why; it must not auto-approve them or silently clear their selection.

Use one compact **Audiobook jobs** panel below scan controls. It has **Pause audiobook jobs** and **Resume audiobook jobs**, with tooltips **Stop the current audiobook operation and save pending books. Finished outputs stay in place.** and **Continue pending books. An interrupted book restarts; completed outputs are not recreated.** Ender's confirmed model checkpoints at book boundaries and stops only the owned encoder process. Pausing does not imply accurate continuation from a partial AAC file. This is separate from Stop scanning; either action's label identifies which work it controls.

States are **Running**, **Pausing**, **Paused**, **Completed**, and **Needs attention**. Show current title, stage, completed books, remaining queued books and failed books. A saved stopped scan does not mean conversion is paused; a paused conversion does not stop discovery. Closing the browser leaves the local service/job state subject to its implemented server behavior, which the footer must state accurately. Stop server must persist pending work safely and leave no unfinished file presented as a completed audiobook. Resume after restart continues pending books, verifies their source/output state and does not recreate accepted outputs or promise mid-encoder resume unless supported.

Source changes between review, queueing and writing invalidate the affected book and pause that job with **Source changed — review required**. Other safely reviewed jobs may continue according to the worker contract. An unchanged completed book with an accepted output record is skipped on later processing. A discovered M4B created by this app must be linked to its job/source group, not accidentally become a new unprocessed source group and create duplicate books. Output missing/changed is **Output needs attention** and requires the reviewed retry path; do not silently overwrite any file. Preserve the authoritative job/recovery record alongside source tag evidence.

Extend candidate Status filters when these states exist: **Ready to create**, **Queued / creating**, **Audiobook created**, **Output needs attention**. The filter still applies to the entire library before pagination. Do not add these options to unimplemented read-only builds or make source Read errors encompass provider waits/converter failures.

## Layout, accessibility and verification

At 1440 and 700 CSS pixels, review and output sections remain stacked, with wrapping paths and concise helpers. Reuse the existing table scroll container for member rows; keep Include/order buttons fully visible or horizontal-scroll reachable at narrow width. Metadata proposals and source evidence use disclosures in normal flow. Buttons have at least 24×24 CSS-pixel hit areas (32px height preferred), visible keyboard focus and sufficient separation; metadata source links are keyboard reachable. Descriptive button labels retain candidate/track context for screen readers. Status changes are polite live announcements, errors identify their actual failing step, and focus stays with the user's control during polling. New controls ship tooltips plus programmatically associated help available on focus. All text and indicators use accepted dark roles; preserve AA contrast. QA reports measured rectangles in every expanded/collapsed, excluded/included, enabled/blocked, running/paused and narrow state.
