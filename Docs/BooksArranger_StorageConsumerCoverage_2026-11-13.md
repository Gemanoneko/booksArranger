# Storage path and native receipt consumer map

This is an implementation map, not release clearance or permission to migrate live data. It was assembled from the typed source classifier and production calls to `facts_match`, `identity_match`, `ancestry_match` and the actual ownership registry. Historical JSON, full-proof hashes and producer origin/boot facts are not rewritten. New handles always return their actual identities.

| State / field | Consumer and admitted behavior | Required hold / exclusion |
|---|---|---|
| Main inventory catalog and `.lock` | `catalog_owner`, `storage_relocation_native`, `runtime_disposition_owners`: exact current catalog file/owner lease, catalog UUID, relocation generation and selected descriptor; `catalog-storage` / `catalog-owner-lock` classes. | Missing descriptor never converts a relocated catalog to writable legacy state. A clone, replaced database, verification-only admission or unavailable root cannot start normal workers. |
| `working_files.path/facts`, attempt directory ancestry | `working_lifecycle`: `working-file` expected-fact bridge plus retained current handle, original size/full SHA and existing producer/CAS checks. Explicit directory entries bridge ancestry. | Unknown members, changed bytes, unclosed producer and reused terminal names remain held. Relocation is not producer closure. |
| `owned_artifacts` temporary/recovery members | `storage_relocation_operator` / `storage_state_ownership`: exact managed path, kind, job, size and SHA establish finite copy ownership. This table has no native-facts column. New cleanup intents record current actual facts; existing cleanup intents use their own class below. | Library/output members are excluded from application-state ownership. `staging-artifact` inventory classification alone grants no disposal authority. |
| `storage_cleanup_files.path/facts` | `storage_cleanup`: `cleanup-file`; exact expected old facts may bridge only through the active generation, with current full SHA/size and existing cleanup state transitions. | Terminal missing-copy proofs stay distinct from a new object at that name. No absence-only deletion proof is manufactured. |
| `cleanup_members.backup/backup_facts`; source-cleanup recovery ancestry | `recovery_retention`, `storage_cleanup`, `source_cleanup`: `recovery-copy` plus typed recovery ancestry, size/full SHA and existing job/intent lineage. | Original book paths are outside relocated managed scopes. Unknown or changed recovery receipts retain their files. |
| `audiobook_replacement_retirements.recovery_json` (M1) | Classifier verifies the exact replacement UUID/path, complete facts, size/full SHA and no pending copy. `replacement_retirement._recovery` and retirement paths compare copied recovery bytes/ancestry through `recovery-copy`, leaving JSON unchanged. | Purged recovery must still be absent; a reappeared object is preserved. Unclosed/unknown proof remains source reconciliation work. Native positive and changed-byte negative are in `test_replacement_recovery_row_reuses_copied_bytes_without_rewriting_provenance`. |
| `producer_recovery_checkpoints.native` isolated-retained proof | `producer_recovery` / typed native retained-fence adapter: `retained-source`, exact stage/ancestry/member mapping and unchanged whole native/provenance proof bytes. | `ownership_authority=false` remains false. Ordinary Clear does not gain authority over isolated work. Producer origin, startup and closure are never relocatable receipt classes. |
| Prepared / origin-only uncertain producer (M2) | Classifier and offline operator deliberately report held. Tests `test_prepared_producer_checkpoint_stays_held_without_copy_closure_authority` and `test_origin_only_uncertain_attempt_requires_source_reconciliation` cover refusal. | Source preparation or verification/enable refuses; copying cannot resolve the uncertainty. Disposed history adds no surviving-file authority, and the independent typed census refuses unexplained survivors. |
| `inplace_edits` whole intent / repair history | Published history is admitted only with an unmoved source and destination, completed job and matching output SHA. Existing library proof verification stays strict. | Active/unresolved or moved repair proofs remain held. The reserved `repair-copy` class is not a blanket implementation for arbitrary whole repair proofs. |
| OpenLibrary mutable database and separate journal | `openlibrary_index`: `index-leaf` and `index-journal` identity adapters retain the immutable old owner JSON while validating the actual new handles. Both members have independent bindings. | Missing journal, unknown owner schema, changed authority or unsupported scope refuses. A database-only binding never covers its journal. |
| OpenLibrary ready/immutable generation, pending owner and completion receipt | Exact `index-leaf` binding plus existing completion token, size/full SHA and owner/index generation checks. | Unknown ready/completion/import-lock provenance is held. Mutable identity compatibility does not waive immutable content verification. |
| Existing output relocation / move plans | `output_rename` keeps actual guarded close/CAS ordering. Completed external-library history remains strict. | Incomplete `output_relocations` operations must finish or be explicitly reconciled at the source. Storage migration does not rewrite their reviewed catalog-native plans. |
| Runtime disposition marker and closed/retained records | `runtime_disposition_ledger` and actual cross-thread owner registry: `file-disposition-control` is finite metadata; copied marker compatibility requires the exact active catalog/generation/root/owner bridge. Closed histories do not reopen old paths; retained histories are distinct from successful deletion. | Pending, malformed or orphan intent never becomes closed success or copied ACL-replay authority. Exact old support-context recovery requires its own owner/marker/producer evidence. |
| Desktop profile, settings and `books-decisions-v1` outbox | Installer pins source profile affinity, SID, original producer and native IDs before stock registry mutation; verified byte copy preserves associated profile data. The external installation selection controls catalog/temp paths before normal startup. | Unknown association is not called preserved. New-catalog mode creates a separate profile and does not replay old pending decisions. Existing/bootstrap-versus-relocated-catalog interaction still belongs to final packaged acceptance. |
| Application package / retained original binaries | Exact trusted package producer and native-created publication receipt; fresh same-parent stage, full membership/SHA checks and no-replace publication. Retaining an old package uses same-volume whole-directory rename and verifies original identities. | Unknown source/Git content, extra files or busy ownership refuses. The accepted 0.27 uninstaller is never executed. A byte-copy backup is not claimed as native-equivalent rollback. |
| Mutable profile/temp/download/log roots and external installation controls | Lifecycle finite runtime schemas and original native root provenance, current membership seals, active installation/catalog references and last-record dependency checks. | Unknown files, source/Git/library overlap and active references remain visible holds. SQL-linked retained-source control bundles need a typed retirement/rehome path; filenames do not supply authority. |
| Maintenance temporary work | Portable `maintenance_temp_dir` and exact three-word native root identity are produced during reviewed installation. Registered uninstall uses that root before NSIS startup; helper copies/journals use the genuine private plugin workspace, outside selected ordinary user state. | No C fallback, no ordinary Temp substitution, no user-data overlap. Sergei accepted retention of the verified NSIS operational executable (approximately 13.4 MB); its exact path, bytes and purpose must appear before and after cleanup. Only the native-pinned, single-stream copy matching the current package uninstaller SHA qualifies. Unknown residue stays held. No automatic or reboot removal is promised. |
| Terminal cleanup registry authority | Private CREATE_NEW UUID key, retained native HKEY, durable pre-mutation intent and actual closed file proofs. Value ownership is expressly limited to that exact private operation key. Unknown subkeys and replacement key objects survive. | Shared parent namespaces are retained. Owned-key-object removal is separate from path absence; a replacement record must be listed, not called removed. Interrupted transactions block normal admission and are inventoried by `--cleanup-status`; automatic adoption is not claimed. |
| User library/source/output folders | Remain exactly at existing Z:/Y: paths. New no-replace publication may proceed. Current provider gate preserves NAS originals and holds unsafe deletion/replacement. | No library is an installer or migration cleanup target. Provider refusal never falls back to a local/personal location. |

The real source readiness assessment still reports one unresolved October 29 producing/active attempt without origin/checkpoint/output intent. Its supported source recovery/confirmation gate remains separate from the code update. This table does not turn that attempt into migration authority.

Registry replacement validation on this host is now model-only after the crash investigation. The native rename regression was removed, and the source-only containment preflight precedes aggregate workers. Historical native-rename receipts must not be replayed or presented as current kernel replacement proof. The retained-handle production mechanism and its finite namespace contract still require the final complete consumer review.

Final acceptance is still required against one committed version and packaged byte identity: relocated existing catalog plus associated profile/outbox, actual I: runtime and NAS continuation/retention, restart/resume, missing roots, installation/upgrade/uninstall, exact filesystem writes, and paired QA/review. Interim component receipts do not substitute for those gates.
