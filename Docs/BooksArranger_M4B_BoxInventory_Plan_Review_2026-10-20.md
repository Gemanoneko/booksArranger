## Finite gaps and required amendment

1. **Fresh facts are not supplied by calling VerifiedFile.facts twice.** Entry caches BY_HANDLE_FILE_INFORMATION in self.info; facts() refreshes extended FileIdInfo but reads size/time/links/attributes from that cached structure. The new helper must explicitly refresh the existing retained object's native facts before and after its observations, compare complete required facts and full source SHA, and revalidate protected ancestry. State exactly which identity API/fallback is accepted; DirectoryBoundary currently records legacy directory volume/index facts, not a full128/birth proof. Do not claim stronger parent identity than is obtained. This requires a reviewed helper-local adapter or separately reviewed minimal production change, not an assumed guarantee.
2. **Context exit is not checked close.** DirectoryBoundary.__exit__ and VerifiedFile.__exit__ ignore CloseHandle return values. The new helper must account for and checked-close every owned source/reader/directory handle, including partial acquisition failures; a failed close makes the observation incomplete. A helper-local narrow adapter is permissible source scope if reviewed; do not introduce a general native_io or process-owner rewrite. Existing owner closure proves process ownership only and is separate from these file-handle checks.
3. **Exact same-object reads and admission.** VerifiedFile provides sequential chunks, not random seek/read inventory. A bounded same-native-handle reader is a suitable finite extension. If a distinct Python read stream is used, bind its Windows handle identity to the retained source while ancestry and deny-write/delete leases remain held; close it before releasing those leases. Path equality alone is insufficient. Explicitly name and pin the existing link/stream admission operation or implement a narrow reviewed read-only check: VerifiedFile itself does not enumerate streams or reject links!=1 on entry. Do not delete streams/markers, weaken masks, request writable/delete capabilities or use a path-only fallback.
4. **Freeze the five-record request and all inputs.** Literal exact ordered job/candidate/revision5/member0/path/manifest SHA/source SHA/size/modified bindings, expected root and helper/runtime/dependency pins must be compared before any source read. Refuse extra, duplicate, missing or changed records. Snapshot current query-only data separately; do not retain a SQLite transaction throughout NAS reads. The two Curran cases stay excluded. A metadata inventory never edits catalog state or marks preservation or source health successful.
5. **Enforce actual cumulative bounds.** The540-second work budget covers all five sequential cases, both complete SHA passes per case, parser traversal and evidence creation; check it between bounded native/hash reads. Calling held.sha256 unchanged supplies no cooperative checks within its loop. Native blocking IO and pre-owner module/tool startup remain explicit limitations, not claims of hard interruption. The existing600000ms owner limit applies only to its owned operation and must retain its original closure reserve. Timeout, forced/overflow, incomplete native ownership or absent checked closure prevents complete acceptance; no automatic rerun or limit increase.
6. **Metadata-only parser and truthful digests.** Bound every offset/extended-size/header arithmetic against file and containing region; bound global box count, depth and allocations as well as each individual read. Unknown fourcc values must be escaped safely or recorded as hex; no embedded private tag payload dumping. Record unvisited/opaque regions and incomplete reasons.
