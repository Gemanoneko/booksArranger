## Ruling

Conditional SOURCE implementation accepted for this finite engineering fixture. No Critical, Major or Minor design finding remains under the explicit trust boundary below. The fixed objective is exercising four native owner/lease/closure cases under a trusted installed Windows base; it does not require demonstrating OS-file immutability before the first trusted observer/startup code. The proposal honestly gives up that stronger outer property. This acceptance does not amend a protected/formal QA launcher, compiler admission, arbitrary executor or any production operation.

For the ENTIRE original outer engineering envelope, the exact approved native_path is an expectation under trusted installed Windows. Its pinned historical path/hash/ID is NOT proof of a current file object or loaded executable. File replacement, retargeting or compromise of that trusted OS base is outside the accepted engineering threat model. No fresh OS fileID/hash/freeze claim may be attached to this outer rule. Do not classify only a purported startup subset, infer parentage from timestamps, filter members, subtract inner snapshots, or claim equivalent ff1177 authority. The fixed pinned Node root/supervisor/controller/worker rules and initial/new process admission stay unchanged.

For EACH tested inner case, the original controller must first acquire the reviewed companion with the same immutable expected-facts bytes and retain its actual live native capability. Outer path trust never substitutes for missing facts, mismatch, closed/discovery capability, file/ancestor/hash/stream drift or failed acquisition. Revalidate before each tested release and after each case's successful original native-zero/retained-signals/EOF closure, keep the same capability through final work construction and require checked close. If an inner closure is uncertain, retain source/runtime/OS leases in the controller's existing uncertainty path for the SAME original outer termination; no cleanup or successful receipt is inferred from that termination. Any operation or close failure keeps the overall group failed.

This divides two claims rather than pretending to prove continuous outside ownership with an unowned observer. The controller is already in the original owned envelope when it acquires the inner-case capability. The observer holds no OS capability and therefore cannot accidentally call a closed one after failed outer closure. No extra owner layer, time reset, bootstrap-only exception or hidden retry is needed or accepted.
