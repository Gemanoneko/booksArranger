## Interrupted old-removal recovery — live-owner design contract

2026-10-20, Senua. **Design only; conditional local implementation acceptance, not implemented capability, runtime clearance or release review.** Basis is primary Ender/Jane's exact proposed same-watchdog recovery contract and the existing pinned relocation/operator reviews. Current unknown/lost-owner recovery remains failclosed. Active watchdog source is excluded; no code, process, native probe or test was inspected/executed for this ruling.

The proposal is defensible only while the SAME original watchdog survives with its retained original Job/process objects. A new JSON record, reopened named Job, numeric PID, process absence, elapsed time or a later launcher cannot recreate this authority. Required finite implementation contract:

1. Before starting the migration child, the trusted watchdog binds a unique invocation to exact catalog native identity, immutable plan SHA/publication and sealed fixed child/runtime/arguments. Create the original child atomically assigned to its original private Job before any execution; no breakaway, unassigned startup window or unowned helper. Retain the root process handle and every observed descendant handle. Native active-zero proof must derive from the original Job object and a complete ownership/membership contract, not a potentially incomplete sampled PID list. All retained original process handles must be signaled. Inconsistent enumeration/accounting or missing required handle/identity evidence refuses recovery.

2. The migration child durably binds that exact owner invocation/catalog/plan/publication BEFORE any old-removal intent can commit. The removal intent additionally binds exact generation, original file/ancestry facts, committed final publication/full digest and previous disposition stage under the existing transaction rules. A crash between registration and intent grants no general retry authority; recovery must find the exact durable intent and match it to the surviving watchdog's original in-memory binding. Durable JSON/SQLite audit is correspondence evidence only, never standalone kernel closure. No catalog/path adoption, mutation of immutable original receipts or reset of the historical attempt.

3. The watchdog waits for original Job active0 AND all retained original handles signaled before recovery admission. An original child exit alone does not suffice. It must drain bounded original output pipes to EOF after closure, distinguish native/pipe failure from success and preserve the first attempt's exact result. If termination/drain/closure is uncertain, record an unresolved outcome and STOP. The recovery child goes into a NEW separately owned private Job atomically before execution; it must not join the original Job whose zero membership it proves. Both Jobs remain under the same surviving watchdog and original enclosing ownership/deadline contract. The watchdog itself must not be a member that prevents either child Job reaching zero.

4. Transfer only allowlisted inherited handles/capabilities directly from that surviving watchdog to ONE fixed recovery entry point. Use explicit handle inheritance lists and minimum query/synchronize access; keep original Job termination authority with the watchdog. Retain the original handles until recovery verification and recovery-child closure finish. The recovery child verifies actual inherited kernel object types/queries, original process identities and signaled state, original Job membership zero, exact watchdog-bound invocation/catalog/plan/publication/intent digest, and its own independently assigned Job identity. Numeric handle values or serialized claims are not enough. Do not expose a generic command runner, arbitrary argv/path callback or reusable named-object capability. The watchdog must enforce at most one recovery launch for that invocation, including launch failure; no hidden retry loop.

5. Recovery acquires the real catalog owner and existing native catalog identity lease anew after the original child has fully closed; it revalidates the immutable pinned plan, durable intent/generation, authoritative derived journal where applicable, committed effective final full bytes/native identity/ancestry, and original presence/absence/identity under normal native leases. `removal_closure` accepts only the exact prior intent bound to the live inherited capability. This closes the old producer lifetime proof; it never substitutes for fresh file/disposition/CAS proof. A retained old file can be removed only through the normal verified disposition path. An absent old file can be reconciled only under the exact persisted removal intent and final-publication/recovery contract. Conflicting file identity, replaced target, changed generation or malformed provenance stays held. No new inference of success from pathname absence.

6. The original600000ms total enclosing deadline covers first-child launch/work, stop/termination, all original pipes/native closure, recovery launch/work, final pipes and recovery native closure. Reserve an explicit finite teardown/recovery budget BEFORE permitting first-child work; no new600000ms window. Late first-child completion or insufficient remaining reserve must decline recovery and retain the unresolved hold. At deadline the owner terminates its retained child Jobs and proves complete closure or returns NO RESULT/unresolved; never prints success before EOF/native closure. This design does not weaken the existing trusted-startup/total-ownership contract or authorize an unreviewed launcher.
