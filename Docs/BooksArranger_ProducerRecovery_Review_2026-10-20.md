## Mechanism and decision

Microsoft documents GetTickCount64 as an unsigned64-bit milliseconds-since-startup API. Its stated timer resolution is roughly10–16ms; the32-bit GetTickCount API instead wraps after49.7days. Use the64-bit API explicitly. A strictly lower later value is a conservative startup-reset inference **within the same trusted Windows execution environment without suspended-machine memory rollback**, not a documented native process-closure handle. [GetTickCount64](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-gettickcount64), [GetTickCount](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-gettickcount).

The proposed combination is a defensible basis for **bounded local implementation** of this exact legacy local-producer recovery path, provided the requirements below are part of the committed implementation brief. No OS reboot, live reconciliation, file disposal or new admission is accepted now. Do not advertise the current Сказка hold fixed until the actual source/receipt inventory and full implemented guard have been independently verified. Boot proof may close a producer classification while other artifact/source holds legitimately remain.

## Findings and required contract

**Major — preparation machine identity is not historical producer origin by itself.** The existing unclosed attempt lacks a historical machine/process identity. Capturing today's MachineGuid/name/system-volume/catalog identity cannot retroactively prove that its producer executed only on that machine. Bind the exact local fixed staging/catalog/attempt ancestry and native directory/file identities at preparation and recovery, retain catalog/operation ownership, and restrict this mechanism to the actual supported local legacy layout. Refuse remote/mapped/removable or moved/replaced/ambiguous staging/catalog locations unless a separate proof establishes producer locality. A lower current-machine uptime must never close a potentially remote producer operating on shared artifacts. No arbitrary job/attempt path or client-supplied identity may enroll.

**Major — snapshot/clone scope must be explicit.** Machine name, MachineGuid, volume serial and catalog file identity are useful handoff checks, but are not cryptographic uniqueness guarantees against cloned disks/VMs. Memory snapshot restoration can resume a captured producer while lowering its remembered uptime; an independently persisted checkpoint could then survive outside that snapshot. The mechanism must not claim to prove process closure across VM memory rollback, machine cloning or mixed catalog/OS restore. Reject known/unexpected restore/identity discontinuities and retain files; administrative kernel/memory-state manipulation is explicitly outside the trusted ordinary-local-restart model, not an undocumented implication of the API. Do not substitute wall-clock, PID absence, current boot alone, optional boot UUID or a successful app restart when these premises fail.

Required bounded implementation details:

1. A server-only OS provider calls the exact GetTickCount64 entry with correct unsigned64-bit restype, validated integer serialization and no truncation to DWORD/float/bool. Freeze versioned typed machine/OS/system-volume/catalog/lock/staging/attempt identities and the complete job/manifest/candidate/revision/source fingerprint. Missing, zero/ambiguous or unsupported native/API values refuse; HTTP never supplies proof values. Optional undocumented boot ID is corroboration only.
2. Prepare is an exact scope CAS checkpoint, serialized by existing operation/review/catalog ownership. Refuse any current conversion/producer, ambiguous attempt, published dependency, changed evidence/source, migration or competing cleanup that can invalidate the snapshot. Persist complete immutable intent plus explicit supersession history using the actual FULL-durability SQLite connection/transaction. Preparation may write only these catalog records and normal SQLite sidecars, never media/working files, queue state, process state or approval. Commit/transport uncertainty must read back durable state before telling the user to restart or allowing duplicate writes.
3. Eligibility is pure and conservative: same complete supported identity/binding, fresh server-derived64-bit uptime **strictly lower** than the saved value, exact live-attempt CAS and no newly registered/current-boot producer. Equality/higher value, unavailable API, mismatched machine/catalog/source/attempt, stale/superseded intent or unsupported restore/locality stays held with typed reason. The proof concerns only the precheckpoint local legacy producer; a current-boot producer cannot be closed by it. No wall-clock calculation or “probably restarted” fallback.
4. Recover is a separate explicit action, not startup/poll side effect. Under the same retained ownership, atomically validate exact latest intent/attempt/source/manifest/candidate and append the accepted OS proof before making the one narrowly scoped closure transition. Retain original active/producing facts and failure/history in the new proof record. Do not call a generic `closed(..., producer_closed=True)` or fabricate prior native process identity. Only the exact accepted producer-proof path may mark that classification closed, once, via expected row generation/content CAS.
5. Closure classification does not retroactively adopt working files. Reuse existing exact producer/artifact receipt inventory, native unique ordinary identities/ancestry/default streams, full source/working hashes and durable per-file removal intent. Unknown/unregistered/replaced/creation-uncertain artifacts remain preserved; missing original sources or publication/recovery dependencies remain held. Normal disposal must hold its native/generation guards through close/absence and ordinary Retry must obtain fresh source/review/admission proof and a fresh attempt directory. No destructive reset, ledger rewrite, queue reset or weaker disposal path.
6. Tests use provider doubles clearly labelled synthetic and private fixtures only. Include64-bit values above32-bit wrap, strict tie/higher/lower handling, sleep/hibernation/app restart with no accepted reset, snapshot/locality/clone limitations, superseding intent races, changed attempt/current producer, catalog/lock/staging identity drift, source/review mutation, API/SQLite/save failure and unknown files. No real restart or live Сказка proof acceptance for tests. Independent component/native/UX review follows implementation; developer case counts are not formal QA receipt.

No Critical or safety-floor violation in the proposed non-mutating preparation mechanism **under these restrictions**. The two Major identity/model gaps above are conditions for implementation, not license to close a real producer on an unsupported premise. If supported local origin/identity cannot be established, STOP with that exact reason; keep the existing hold and all files. Do not broaden the mechanism to make a fixture pass.

## UX review

It does not promise every real restart will verify, exposes equal/higher-uptime missed-window behavior, forbids automatic checkpoint replacement/restart, preserves uncertainty after connection loss and never offers Clear working files as a substitute. A newly accepted startup reset alone does not enable conversion. No UI geometry or actual behavior was measured here.
