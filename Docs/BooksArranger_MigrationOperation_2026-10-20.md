# Offline output migration operation — implementation checkpoint

2026-10-20, Ender. Engineering checkpoint only; no production invocation, formal QA receipt, release clearance or live copy/removal occurred.

The offline planner and per-publication operator now exist in migration_planning.py and migration_operation.py. Every entry point acquires the same native catalog_lock used by production interfaces before catalog enrollment or worker access. A running app therefore refuses the operator. The operator starts no app, scan, recovery worker or queue and never resets queued work. Any running audio job or active source cleanup refuses the operation. Normal supported app drain/Quit and a verified no-focus production reopen strategy remain prerequisites before live use.

The planning command requires explicit pinned configuration JSON (--config and --config-sha), an absent --output-plan pathname, and optionally exact pinned user decisions (--decisions and --decisions-sha). Configuration contains database, legacy roots, additive audiobook_sources and audiobook_output_root. The existing source must remain Source1. Plan data stays outside catalog data and source/output libraries, is CREATE_NEW, fsynced, native-read back and SHA-bound; existing plans are never overwritten. Failure after enrollment but before plan publication leaves only idempotent planned catalog bindings, with no media operation; a fresh plan can be regenerated from the same exact accepted scope.

Planning enrolls one current importable publication per Ready book, following the existing representative policy: active replacement; otherwise unique corrected Chaptersv2; otherwise unique Chapters; otherwise base. The plan records active_variant_counts, exact original/effective destination and frozen binding SHA. Superseded base/chapter variants, retired history and recovery media are retained in original locations and are not duplicated into the destination import tree. Add Folder to Library must target only the final sorted tree after final verification. The initial385 Ready snapshot is a count of books, not all owned media artifacts. A final after-drain variant/history inventory is required before reporting completion.

Native current-output proof, approval revision/fingerprint, canonical review digest, source membership/order/hash proof, cover correspondence and completed cleanup are checked before enrollment and again under each operation capability. User routing evidence is actor=user and exact candidate/fingerprint/review-bound; the11 confirmed Warhammer/Дозоры choices are stored in BooksArranger_RoutingDecisions_2026-10-20.json. A changed snapshot is held, not guessed or silently rebound. The planner checks case-insensitive collisions across all planned books and available space for second copies plus reserve before any enrollment.

Each --publication operation uses one resumable bounded native owner invocation, not one unbounded385-book operation. The operator verifies exact plan SHA, frozen binding, persistent catalog journal and FULL/EXTRA durability. Worker stage commits return actual catalog row/event digests and owner identity. Invalidation shares the binding commit transaction, clears both location verification cache rows, adds effective owned output provenance and preserves historical original ownership rows. The native worker independently fresh-hashes held original and destination. Sealed media reuse requires the supported immutable validation SHA/size/profile contract; derived chapter reuse additionally reconstructs the authoritative journal, validates original receipt and freshly matches its accepted SHA at each scope check. No arbitrary passed flag supplies media truth.
