1. Route comparison runs at the beginning of actual attempt_boundary, before retained-parent hashing, working admission/cleanup/archive, new attempt UUID, source/hash/copy or destination IO. Compare canonical ordinary effective root and exact planned full destination using existing frozen metadata with only routing policy upgraded for calculation. Missing output_root defaults only to frozen source root; explicit null/malformed fields refuse, never get silently repaired. Matching actual root/path passes even with an old version label. Do not reinterpret canonical title/author/provider evidence or force metadata approval.

2. Bind the observation to the exact whole job/manifest hash AND effective configuration/source-output root-policy snapshot (digest/generation). Recheck that policy at hold CAS and before typed projection/explicit Retry. Changed policy must make the observation stale or create a separately recorded refreshed exact observation; do not display one proposed target while silently treating it as approval for a different target. Desired paths are server-derived comparison data; HTTP never supplies authority or path arguments. A hold is not source/metadata/media approval.

Same BEGIN IMMEDIATE must require exact unchanged entire pending row, valid canonical manifest digest, no output, NO publication-intent key (even an empty/malformed one is not a waiver), newest/current/non-set-aside candidate and applicable revision/currentness. CAS only state/reason/updated plus a separate typed observation record. Preserve manifest/hash/job/journal/attempt/created verbatim. A changed row, policy, stop/drain or failed/uncertain commit refuses without partial hold state/evidence; verify rowcount and durable readback before returning an acknowledged hold. No direct SQL operator repair or retry loop.

4. Pause/Quit must be rechecked immediately before CAS/admission continuation, not merely at loop entry; hidden startup/published verification/retention never runs this queue pass. After a successful explicit-start hold, continuing to the next already pending item is allowed under existing stop/drain checks. It must not enqueue a successor, convert the held item, cancel old work or trigger shared automatic Start. Typed mismatch is distinct from generic working/native failure and must retain truthful reason.

5. Explicit existing Retry is the only child-admission action. Exact durable typed hold must match whole parent/manifest/current policy and normal Retry/current candidate eligibility. SAME-root hierarchy-only mismatch uses the same route-child path, avoiding an old-manifest requeue loop. Fresh source/order/hash/review/cover/working/space checks remain mandatory, then whole parent/group/context CAS and one-parent/one-child relation admit a DISTINCT fresh job/attempt. Existing nonnull prior attempts or working debt are not covered by the current attempt-null case and cannot gain a cleanup/admission waiver; refuse/route through the normal separately verified working rules. Original held row stays unchanged after its hold, including journal/manifest/history. No Start-over/discard trick.

6. Desired-root/target preflight is read-only and native-safe, bound to the same freshly computed route/policy. Unavailable target, unsafe ancestry or unowned collision refuses. It grants neither output ownership nor permission to replace. Existing no-replace publication remains the final race gate, including any collision appearing after preflight. A changed source/review/provider choice or manual evidence requires its actual normal remedy, not a destination hold override. New retry manifest must pass the same earliest route check and existing exact retry relation/Ready guards.

These must leave old rows/bytes intact and create no new UUID/source IO or automatic child.

Keep the proposed instrumented zero-call mismatch test for working admission/archive/UUID/runner/copy/cleanup and assert attempt-null/no staging/full manifest-journal-created invariance. Run actual small legacy→typed hold→explicit distinct child→native output→normal Current/Ready for root-change AND same-root hierarchy change; do not seed fake output/cache proof.
