# Protected native input contract V2 — decision proposal

DOC ONLY. Existing C++/POST sources unchanged; production refuses. V1 holds Node/bootstrap/opaque guardian-plan bytes, not the complete native-before-child authority required by the frame. Its eight keys are state, node_sha256, bootstrap_sha256, operation, plan_path, plan_sha256, source_root, run_parent.

Choose one entry-only V2 contract, reusing canonical protocol2 context/manifests without changing the canonical checker. Keep those eight keys; add invocation_id, context_path/context_sha256, policy_path/policy_sha256, runtime_path/runtime_sha256, source_sha256, watchdog_sha256. Unknown/duplicate keys, other operations and V1 refuse. Digests below mean actual held file bytes, never reconstructed JSON aggregates or authority supplied by JSON claims.

| Held bytes / literal | Definition and mandatory join | Producer → consumers |
|---|---|---|
| BOOKS_QA_REGISTRY_V2, ASCII LF, ≤16 KiB | Fixed entry/roots, one invocation, all exact refs/digests above; plan remains the guardian plan. | Registry template/provision → PRE, C++, fixed entry, POST |

Both match registry/policy. | Existing protected provisioning → PRE, C++, POST |
| BOOKS_NATIVE_RESULT_V1 | One opaque base64 payload plus terminal, exact lengths/canonical encoding/EOF. Terminal repeats invocation/all held digests; parent stderr empty. Raw payload ≤12 MiB−8 KiB, terminal ≤8 KiB, total stdout ≤16 MiB. | C++ only → strict POST parser |

Proposed closure ceilings: 100000 unique files/directories, 259-character paths, 1 GiB per file, 2 GiB total unique file bytes; larger inputs refuse pending review, not silent expansion. These are proposed limits, not measured-fit claims. Native must independently reopen/lease ordinary files, default streams and ancestry; protect registered installation inputs, hash exact held bytes and verify complete inventories BEFORE releasing the one fixed child. Keep leases through Job-zero/signaled members/EOF, then checked closes. Keep monitor through outer frame writes; actual original tool termination after monitor teardown is separately required.

Necessary future ownership only: operations.registry.template, provision-protected.mjs, qa-context-assembly-v2.py (sidecar), protected-admission.mjs/checks, books-qa-watchdog.cpp, launch-books-qa.mjs, protected-admission-result.mjs/checks, dispatch-books.mjs and deployed-host.candidate.mjs. Reuse launcher parseRegistry/validateGuardian and guardian protocol2 verifyManifest semantics; JS validation cannot lend native authority or permit direct JS entry. Canonical five checker helpers remain unchanged.

OPEN: Senua input-schema/limit decision; native bounded decoding/held-closure implementation and build evidence; protected image/ACL/bootstrap installation proof; real trusted host original-tool association/default-shell observation. POST consumes one privately pending actual call/invocation and actual exit0/duration/EOF, never caller JSON or disk receipt. No v3 identity parity, same-user injection resistance, generic executor or new owner stack is claimed. Until those gates exist, no frame or PRE/POST shape unlocks production.
