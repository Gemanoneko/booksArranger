## 1. Already converted, extra source copy

For the demonstrated `Неисповедимый путь 2` candidate, a verified duplicate **source** is a separate file from the old source that was already removed after conversion. Similar names, visually identical Unicode spellings, a matching destination path, or an existing M4B alone never grant the UI permission to say “copy” or “removed.” The finished audiobook stays distinct from the extra source. Ender's full recording/source proof, checked completed output and protected deletion/receipt rules decide the state; the renderer uses typed facts, not name or path comparison. Preserve the exact source path in Technical details so NFC/NFD spellings are not conflated.

Reuse the current candidate status/hint, Audiobook jobs activity, existing output and Source cleanup facts, and the ordinary polite status announcement. **No new button, confirmation, dialog, toast, filter, settings option or bulk action.** Sergei requested automatic removal for this proved case. Keep `Remove this copy` and its confirmation only for its existing manually offered cases; do not silently press that control on his behalf. An ordinary unrelated or unproved collision continues to use the existing **Name taken** question and keeps its file.

| Backend-confirmed phase | Candidate status and hint | Activity / result |
|---|---|---|
| Recognized match; checks pending or running | **Checking extra source** · `Checking this source against the finished audiobook.` | Existing job activity names this book. Do not imply removal has started. |
| Protected removal in progress | **Removing extra source** · `The finished audiobook stays in Audiobooks Sorted.` | Use existing Source cleanup progress only for confirmed file receipts, never for hash/proof progress. |
| Removal durably confirmed | The extra-source candidate leaves active/attention lists and counts on the next authoritative refresh; the completed book remains **Audiobook Ready** at its verified current output path. | Existing jobs/history records `Extra source removed. Finished audiobook kept.` Show this only after exact-file removal and durable completion are confirmed. Do not count the old source's prior removal again. |
| Match or output proof fails | Existing **Name taken** if this is still an ordinary collision; if the backend identifies a protected hold, **Extra source kept** with `{specific check or file} could not be verified. {supported next action}`. | Keep the extra file. Never offer an automatic deletion claim or a renaming fix for an unresolved cleanup hold. The backend decides whether a later scan/retry can resume; do not invent a Retry control. |

These strings replace **Name taken** only after the backend has recognized this exact completed-conversion relation. The transition can be brief; do not delay work just to display it. A completed status must remain discoverable in existing job history after its candidate row disappears. Technical details may show exact paths, fingerprints and diagnostics; the row stays plain language. No output path, metadata, recovery-copy or unrelated source is described as deleted.

## 3. Edit names must finish loading

Keep the existing **Edit names** button and tooltip: `Correct this book's title, author, series or universe. Nothing is converted or moved.` The current editor's fields are **Title**, **Author**, **Series**, **Number**, **Universe**, and the existing **Collection of stories** choice. On a question row, share the existing Title/Author and inline Series/Number controls; never display a second copy of a field. Series and Number remain paired under the current validation. Suggestions are optional; a missing suggestion list does not hide or disable an editable field.

| State | Existing row/editor behavior and exact copy |
|---|---|
| Request pending | In the editor, `Loading these names…`. Keep Edit names associated with this editor. No blank fields that could accidentally save as cleared values. |
| Valid answer | Replace Loading with the fields above and existing **Save** / **Discard** controls. Prefill current saved values; retain any title draft already in the row and the separately saved folder. Keep the existing Place and destination lines. |

| Save pending | Existing inert **Saving…** face and `Saving these names…` status; keep all entered values and focus. Do not claim they are saved yet. |
| Save accepted | Existing `Saved names for {title}.` result, plus **Goes to {path}.** only when the backend confirms a current destination; for an already finished book, retain the existing `The finished audiobook in Audiobooks Sorted keeps its name.` wording when that is the actual result. The existing button/field tooltips and accessible names remain. Do not add a second Cancel control. Save uses the current one-draft preview: editing Series/Number/Universe never silently resets Title, Author, the chosen folder, or an unsaved title entered before opening. Keep Enter for preview and Ctrl+Enter for the existing guarded Save/Approve behavior. Loading, success and failure updates use the existing polite status/alert patterns without moving focus except on explicit opening, Discard, or terminal load failure.
