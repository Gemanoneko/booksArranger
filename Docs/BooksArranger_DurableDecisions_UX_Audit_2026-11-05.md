## Findings sent immediately to Ender and Jane

1. **Newer track confirmation can be lost (Major UX correctness).** `save-tracks` snapshots `trackDraft` (order and included files) and compares only that object after acceptance (`web/app.js:1470`). **Source coverage**, **Playback order** and **Keep source tracks as chapters** stay enabled during the Save (`:598–599`), and their change handlers set `trackDirty` (`:1472`). If one changes while the Save is in flight, the equality test still passes, clears `trackDirty` and can restore the older accepted checkbox values. Compare all submitted checkbox values before clearing dirty/restoring, or keep those controls inert until the receipt, while retaining focus. The second press must save the newer choice.
2. **Newer metadata conflict choice can be lost (Major UX correctness).** `Save choices` sets `saved.pending` and inerts only its button (`web/app.js:1352–1359`); radio inputs remain changeable (`:1367–1400`). The handler snapshots `choices` but accepts and renders the older result if `editSeq` matches, without comparing current `saved.answers` to the submitted choices (`:1400–1421`). A radio changed during the request can be overwritten while the line says **Choices saved.** Guard the newer radio choice or keep the radio inputs inert during the press; success must describe only the accepted snapshot.
3. **Candidate metadata Approve has the Save verb (copy mismatch).** `decisionLine` treats `review` as `Saved metadata for {book}.` (`web/app.js:229`), and **Approve candidate metadata** calls it with action `review` (`:1156`). The spec requires **Approval saved for {book}.** when `approve:true`. Distinguish that payload from a metadata draft Save; do not relabel the Save path.
4. **Paused Resume help still says Start (copy mismatch).** The paused button face, accessible name, tooltip and detail use **Resume automatic processing** (`web/app.js:2430–2460`), but the static automatic help and footer still say `after server restart, Start continues it` (`web/index.html:51,148`). The unavailable fallbacks in `renderAutomaticEligibility` also say **Start** even while the paused face says **Resume** (`web/app.js:2435–2444`). Make static help state neutral and use the current Start/Resume verb in unavailable reasons; preserve Stop behavior.

The first two findings block a source-only UX GO because the success receipt may conceal a later unsaved edit. Findings 3–4 are bounded copy corrections already assigned to Ender. Accepted-but-not-yet-applied approval also needs a private fixture: `askSettled` keeps the old ask when a durable receipt is `accepted` or `needs_review` without an applied job (`web/app.js:4938`), and `askMode` relies on the refreshed row/`askDone` rather than querying durable owners (`:3197–3210`). The backend may resolve the row promptly; source alone cannot certify that a reopened list suppresses a duplicate Approve and shows the accepted pending state before application. Check that boundary with the actual list response, without assuming a failure.
