## Actual Comics reference

Read-only reference: the actual Comics Organizer, thread `01a0fb82-8816-7090-8516-bebbdf88aafe`, source `C:/Users/<user>/Documents/Codex/2026-10-02/le/outputs/comic-metadata/static/index.html`. Its row actions are **Details** and **Folder**. Details opens a dialog showing a cover, full local path and embedded metadata; Folder opens the selected file's containing directory. Its `/api/cover` returns local archive artwork; `/api/open-folder` resolves a library record and reports an unavailable folder. These were inspected as source only; no live Comics controls, native folder window or user browser was opened.

Apply the same useful pattern in Books: a clear row action for cover/metadata and one for the source folder. Reuse Books' existing details panel rather than introduce a duplicate modal or separate editor.

## Row actions and inspector

Add a trailing **Actions** column. File rows have **View metadata** and **Open folder** quiet buttons. Candidate rows have **View metadata** plus **Open folder** when their reviewed source locations share one book folder. Their accessible names include the file/candidate title. Tooltips: **Show metadata, artwork and the file location.** / **Open this source file's folder in File Explorer.** Candidate folder tooltip: **Open this book's source folder in File Explorer.** Keep the toolbar's existing **View** selector labelled View; do not call the new action simply View, since its meaning differs.

View metadata selects the record and shows the existing details panel. Its heading is **File metadata** or **Book metadata**. Bring the heading into view and focus it only on this explicit action; polling must never scroll or move focus. Existing row selection remains available. Do not reset dirty canonical fields just to inspect the same selected record. If selecting a different record would lose edits, retain the existing save/discard behavior; no new automatic save, overwrite or unrelated confirmation flow.

Place read-only metadata inspection above the existing editable review form. It has up to three clearly titled sections in normal document flow:

- **Source metadata**: values actually read from the selected source file or candidate members, with exact source location and read status. Artist is **Artist — role unverified** where it has not been independently verified. Candidate values are summaries of member evidence; mixed values show **Different values across source tracks** with an inspectable member/value list. Do not present the first track's tags as settled book metadata.
- **Approved output preview**: only when an approved current metadata revision exists. Show title, verified author Artist, series/number, recording language, narrator/comments, selected cover and proposed path. Label **Not written to a file** until the corresponding output is created. Draft edits are separately labelled **Draft preview** when displayed; they cannot appear as approved. Changed approvals show **Review required** and retain the provenance distinction from the committed addenda.
- **Created audiobook metadata**: only for a validated completed job. Show actual values read from that output, its actual cover and full path, plus **Output checks passed** and the separate recording-completeness / Apple Books sync status. A saved approved preview is not a substitute for reading the created file. Missing/changed/unreadable output shows **Output needs attention** and marks any preserved snapshot as **Saved output snapshot**.

Use compact labelled facts, not an unlabelled JSON dump: title, author/Artist evidence, album/series/number when present, recording language, narrator/comments, format, duration when known and artwork source. Preserve existing raw tags in a collapsed **All source tags** disclosure; unknown/unavailable values show their actual status rather than invented metadata. Do not insert empty rows for every unsupported tag. Original-work language and recording language remain distinct.

## Artwork and library boundaries

Each displayed artwork is associated with the metadata section it belongs to. Source artwork carries its source file/path or source record; approved artwork carries its selected source and provenance; created output artwork is the cover actually embedded in that output. Use one preview image per section with maximum width 230px and maximum height 310px, `object-fit: contain`, so the complete cover stays visible. At wide width, cover and metadata can sit beside one another with a 16px gap; at 700 CSS pixels they stack, without shrinking metadata or forcing the cover over controls. Alternative source covers are inspectable in a collapsed **Other source artwork** section and never silently replace the approved cover.

When the candidate has several source covers, label the displayed image **Source artwork from [filename]**; it is an example from that source, not a verified recording cover. Show **Cover not found** if extraction completed without an image, **Cover preview unavailable** if unsupported, or **Cover could not be read** with the concrete failure if reading failed. No broken-image icon, unrelated placeholder image or fabricated cover. An unimplemented format's cover extraction must not be described as a scan error or block viewing readable metadata. Existing selected-cover review controls remain the only way this inspection affects a draft cover.

Files view works for audiobook tracks, existing M4B, podcasts and ebooks; display embedded/available local artwork only when supported. Podcast details show show/episode, dates, GUID/feed and preserved classification where available, and remain outside book creation. Ebook details show existing book metadata and format without conversion controls. Companion files show their actual type/path and **No book metadata available** when appropriate; image companions may show the actual local image, clearly **Companion artwork**. Missing/unreadable records retain their error details and any labelled saved snapshot. No metadata approval or merger is unlocked solely by using View metadata.

## Opening folders

Open folder opens only the selected source's containing folder; it does not launch the book/audio file. If a candidate genuinely has multiple source folders, replace the single folder action with **Source folders**, tooltip **Show the folders containing this candidate's source tracks.** It expands a short list of unique full paths in the inspector, each with **Open folder** labelled by that path. Do not pick a guessed common ancestor, silently open many Explorer windows or hide which folder will open.

For a completed validated audiobook, add **Open output folder** beside its full output path, tooltip **Open the folder containing this created audiobook.** Use the actual recorded job output, not a future destination preview. A proposed destination does not cause the app to create or open a folder. Source and output folder actions remain separately named in details even when both locations are the same.

Folder actions are explicitly user initiated. While the request is pending, disable only that action and show **Opening folder…**. Success restores the button; no unnecessary success toast. Failure shows an adjacent concrete message such as **Folder unavailable. Connect the library drive and try again.** Keep the record selected, source path visible and review drafts intact. Backend resolves the trusted selected library record or completed job, applies the existing local-request protection and verifies availability; the UI does not submit an arbitrary editable path for execution. No external browser links, shell command text or path typing is added to this feature.

## Layout and verification

Row action buttons remain in normal flow, 32px comfortable height, at least 24×24 CSS-pixel hit areas, with 8px separation. Actions may wrap within their table cell; they must remain reachable in the existing horizontal table scroll at narrow width. Do not hide the Actions column at the narrow breakpoint. Every new button/disclosure ships its tooltip and programmatically associated help, visible keyboard focus and contextual accessible name. Use the accepted dark text/border/focus tokens and text states alongside color. The metadata panel uses native disclosures and existing section spacing; no sticky image, floating controls or overlay on the form.

QA checks metadata plus actual cover for MP3/M4B where supported, differing member Artist/cover values, no-cover/unsupported/error states, approved-versus-draft evidence, validated output-versus-saved snapshot, EPUB/FB2/podcast/companion boundaries, one/multiple source folders, output folder, unavailable drive, request failure and retained dirty review. At 1440 and 700 CSS pixels measure cover/control/form rectangles in all expanded states and verify no overlap or clipped targets. Use isolated fixtures and mocked folder opening for automated tests; do not open Explorer, native apps or Sergei's actual folders during QA. Real folder launch can be verified only within an explicitly authorized native interaction window; otherwise report that boundary honestly without blocking the mocked route/UX checks.
