## 1. Counts must name their scope

Keep the existing `X converted out of Y approved books` progress line. Replace its vague helper with **Approved books passed metadata and source-order checks. Converted books also passed output and cleanup checks.** Approval is not a count of source files or all discovered books. At the inspected release, `progress_books` requires a current candidate/context revision, `approved_scope`, source hashes, membership/order/coverage checks and a usable saved cover; conversion adds the representative completed job, matching current output receipt and required cleanup. Ender must verify the same predicates after the multi-source/migration work.

Add a plain count line below it: **N book candidates found · U not approved**. N is all current catalog candidates across configured audiobook sources, deduplicated by the backend's candidate identity, before pagination/search/status filtering; U is the set difference from that same snapshot's approved IDs. This describes catalog knowledge, not all books physically present on an unscanned drive or unique literary works. Helper: **Candidates are discovered book groups. Scan every source to include its books.** Do not subtract totals with different root/revision scopes. Missing telemetry reads **Book candidate totals unavailable**, never zero or a guessed subtraction.

The jobs summary's existing attention number counts output/job/recovery attention, not every held metadata candidate. Render it as **A output issues** and add a quiet adjacent **Show output issues** button (tooltip: **Show audiobook jobs and finished outputs needing attention.**), opening the existing `output_attention` filter. Add **H held for metadata** and **Review held books** (tooltip: **Show books held for missing or conflicting metadata.**) only when the backend can supply that exact distinct metadata-held predicate, opening the matching held category. Do not relabel all held candidates metadata: recording/order/source issues remain distinct. These counts can overlap with approved/converted; do not present them as a partition or add them to calculate the total. Unknown counts read **Unavailable**. Whole-library counts remain stable when search/page changes; visible-list count identifies its filtered scope.

No new approval gate. Automatic processing still approves confident candidates. Manual approval remains the exact-revision **Approve candidate metadata** action and does not confirm tracks or clear source/recording conflicts. The helper beside approval lists the actual unsatisfied requirements. Explain the live totals to Sergei from measured predicates before claiming the count changes are delivered.

## 2. Metadata help within attention

Extend the existing Manual review disclosure; do not build another editor. On a held metadata candidate, and in the selected details' Automatic result section, add **Edit metadata** as the first relevant remedy (quiet, minimum 104×32 CSS px). Tooltip: **Enter missing metadata and save it as evidence for this book.** Accessible name: **Edit metadata: {title clue}**. It selects the same candidate, opens Manual review, brings the Metadata heading into view and focuses the first missing/conflicting field, or Canonical title if none is identified. View metadata remains read-only inspection. Opening the editor never clears the selected attention reason or starts a job.

Keep output-only failures in their existing reason strip; editing metadata is offered there only if that book also has a metadata hold. Unsupported M4B, storage and recovery problems must not imply metadata can repair them. The existing Held filter must show missing/conflicting metadata candidates even when no audiobook job exists. Its status uses typed backend cause codes, e.g. **Held — title missing**, **Held — author uncertain**, **Held — metadata conflicts**. Show actual missing field labels and disagreements immediately above Metadata. Unknown causes retain a readable factual reason; never infer them from English text or historical counts.

Retain **Save preview metadata**, with tooltip **Save these values as a draft and a metadata source for this book.** Change its completion note to **Metadata source saved. Review or check this book to continue.** The same save persists a reusable manual-source record independently of a canonical draft and temporary automatic hold. In View evidence, identify it as **Entered by you**, with saved time, entered values and Manual evidence note. A blank optional field is unspecified, not evidence that another source is wrong. Explicit reviewed standalone and no-universe decisions must be represented separately from unknown values.

Add **Check metadata** beside Save (quiet, minimum 104×32). Tooltip: **Compare saved manual metadata with the other sources and check this book again.** Help: **Saved values are evidence. Conflicting sources still need review.** Disable while unsaved edits exist, with visible **Save your edits first.** It saves no implicit changes, clears no manual data and initiates only the backend's metadata re-evaluation. Pending **Checking metadata…**; success shows the acknowledged result, such as **Metadata checks passed**, or actual remaining holds. Do not promise conversion; queue eligibility uses existing checks.

Reuse the current proposal controls for explicit acceptance of conflicts. Show manual and other proposed values side by side in the evidence disclosure; **Use as proposal** fills drafts only and has its existing tooltip. No unconditional manual priority, confidence inflation, inferred approval or silent acceptance of conflicting sources. Source outages do not prevent saving manual evidence.

Saved manual evidence survives lookup, Check metadata, Start over, Let the app handle it, automatic processing, rediscovery of unchanged sources and restart. Those actions may invalidate canonical approval or clear the canonical draft according to their existing contracts, but must retain source evidence. Any existing discard confirmation must distinguish **saved review** from preserved **entered metadata**; remove claims that all entered information will be lost when it will be retained. Existing unsaved-draft protection still applies: no polling/lookup overwrite, no silent navigation loss. Source identity changes preserve evidence with its original binding and mark it stale until re-associated; never silently apply it to a different book.

## 3. Folder rules and existing editor

Add **Universe (blank if none)** immediately before Series / cycle in the existing two-column review grid; tooltip **Group this book under a shared universe, with its cycle inside when present.** Helper: **Leave blank only when this book has no shared universe.** Blank/unreviewed stays unknown in evidence; the accepted metadata decision must distinguish these.

Rename the anthology checkbox to **Short-story collection**, tooltip **Name this collection with its cycle or universe and Short Stories.** Helper **Place it directly in its applicable cycle or universe folder.** Do not use collection type to infer multiple authors or disable author credit. Preserve the verified author for output tags. Rename the multi-author checkbox to **Cycle has multiple authors**, tooltip **Place this cycle at the library root, or inside its shared universe.** Preserve verified authors even where the routing does not use an author folder. Remove obsolete Сборники hints and routing claims in this flow. Native/non-browser consumers that share these fields must use the same semantics.

Exact hierarchy supplied by Sergei (Books denotes files; no extra literal Books folder):

| Accepted identity | Relative output location |
|---|---|
| Single-author cycle | `Author/Cycle/book.m4b` |
| Multi-author cycle | `Cycle/book.m4b` |
| Universe with cycle | `Universe/Cycle/book.m4b` |
| Universe standalone | `Universe/book.m4b` |
| Collection within cycle | Directly in the applicable cycle folder |
| Collection within universe without a cycle | Directly in the universe folder |

Collection filename stem: **Book Name - Cycle or Universe Name - Short Stories**; omit Book Name and its following separator when no book name exists. Use cycle name when the collection belongs to a cycle, universe name when it belongs directly to the universe. Do not invent either name. Missing both is a routing hold requiring a product decision, not silent fallback to Сборники. Standalone books outside universes retain the existing author routing. Keep existing normal-book filename/order conventions unless they conflict with the new explicit hierarchy.

Show **Output folder** and the complete proposed path directly after routing controls, updated from the authoritative backend preview. Helpers/errors wrap; do not hide the path behind ellipsis. Unsaved preview must say **Unsaved destination preview**; save does not move an existing file. Universe/collection metadata is not guessed from directory names alone. Ambiguous cycle author scope or universe membership remains held with **Confirm the cycle or universe** and a usable editor.
