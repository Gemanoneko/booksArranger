## Ruling

Accept the finite diagnostic design for source implementation after this ruling is pinned. The bc2a returned closedfalse/native:null error is an observability finding; no OS/rights/exit-race/buffer/ABI cause or closure is established. The proposed fields add diagnostic context only. No new Critical/Major or safety-floor objection under the exact requirements below. A future source packet and separate new-group plan/admission/invocation review are mandatory; no retry or reconciliation of an old group is granted.

## Required implementation contract

- At the existing failing QueryFullProcessImageNameW edge, capture the native error before any other Win32 API call on that same calling thread. State the exact Koffi/native error-preservation mechanism and its evidence in the source packet. A separate JS/FFI GetLastError call must not be presented as certainly preserved unless that bridge is proven; zero, unavailable or malformed error stays explicitly unknown with capture status. No new compiled helper or standalone native probe is implied by this design. Never infer an error code from the generic message.
- Pass explicit bounded phase context for initial-supervisor, new-member, retained-list, retained-final and close-sample; add a fixed subphase if close-sample must distinguish its own list/final edges. Record expected PID, requested handle access mask, input capacity1025 UTF16 characters, observed returned DWORD length if readable, exact owner UUID, and existing validated prior PID/creation/image only when actually present. Initial queried PID/creation facts not yet independently validated must be labelled observations rather than prior authority. No handle/pointer addresses, arbitrary object dumps, environment, stacks, other-process inspection or follow-up native calls to fill fields.
- Preserve the first real image-query failure context across later sampling/close errors; later close context may be separately labelled, never silently overwrite the original cause. close currently reduces exceptions to message strings: the implementation must explicitly carry the bounded typed diagnostic through the SAME-instance terminal evidence and diagnostic serializer without changing native acceptance fields or interpreting that diagnostic as closure proof. Avoid storing arbitrary Error/prototype/getter objects. Where capture cannot be preserved, describe diagnostic unavailable and retain the original generic query failure; do not fabricate detailed retention.
- A failure still fails exact image/PID/creation/membership admission or sampling. closedfalse/nativeunknown remains uncertain; all existing checked cleanup is attempted with unchanged validated-supervisor kill eligibility, incomplete-list floor and retained-handle lifetime. No cached-image acceptance, post-exit validation skip, PID reopen/adoption, broader rights, permissive buffer retry, error-code special case, changed wait ordering, arbitrary termination, Jobzero waiver or changed uncertainty hold. Any such behavioral change requires a separate review.
- Extend only explicit typed diagnostic fields in the owner terminal evidence/diagnostic whitelist and their pure controls. uint32 error and masks must have integer/range validation; paths/images/PIDs/phase strings retain fixed bounds; unsupported/null/zero values remain explicit. Identity/native snapshot acceptance and success wire shape stay unchanged except optional descriptive diagnostic data in the declared separate field. Same600000 absolute budget,570000 outer stop, inner reserve, diagnostic598000 floor and16MiB total quota remain. Capture failure/overrun cannot reset time or suppress original refusal.

## Mandatory meaningful controls

1. Each fixed phase fails image query: recorded API/phase/PID/rights/capacity correct; initial supervisor rejection never gains termination eligibility.
2. Fake failing image call sets an error; an intervening fake native call would clobber it: verify capture precedes all subsequent native calls. This pure ordering control does not establish actual FFI error preservation.
3. Error0, negative, overflow, noninteger, missing and throwing capture: explicit unknown/refusal, no guessed cause or accepted identity.
4. Prior validated identity only on retained paths; inconsistent PID/context rejected, no raw handle serialized.
5. Original image failure followed by different close-sample/close failure: first context remains distinguishable and original refusal remains; result/evidence closedfalse with no fabricated zero proof.
6. Diagnostic serialization/native write/readback/close/quota/reserve failure: original query failure survives, existing safe cleanup still runs. Getter/proxy/malformed diagnostic objects refuse without execution.
7. Successful image query retains existing identity validation, owner proof and fixed wire contract. Existing wrong PID/image/creation, reused PID, assignment throw, rejected-handle cleanup, incomplete list and checked-close controls must remain.

Only fake tests may inject failure context. Actual native error/thread preservation remains unrun until separately admitted evidence. Entropy one-call instrumentation is a separate pinned scope; a combined source packet must distinguish both changes and retain exact pins. f528/c194 review bytes and old evidence remain unchanged. Old native closure UNKNOWN and original compiler NO RESULT are unaffected.
