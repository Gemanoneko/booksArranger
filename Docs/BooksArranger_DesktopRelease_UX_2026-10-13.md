# Books Arranger — desktop release UX (2026-10-13)

Owner: Judy. Implementation: Ender. Scope: Electron M1 §7 the approved idle-only M2 update notice and first-run data-folder selection. Binding decisions: Brief, “Sergei decisions — search channels and release stack” and “Desktop app (Electron) — milestone 1”. This spec preserves close-to-tray, graceful full Quit, saved queues and paused launch. It does not authorize immediate Quit, cancelling an accepted Quit, automatic processing, moving data or changing source/recovery safeguards.

## Shell and tray

Keep the existing 1280×860 initial window and 950×650 minimum. Retain native Windows title bar and window controls. Title is “Books Arranger”. Replace the prototype badge with “vX.Y.Z”, taken from the loaded engine version; show “Starting…” until that is verified. The tooltip is “Installed Books Arranger version”. Remove a production DevTools menu; retain ordinary text editing keyboard behavior. Alt+F4 and the title-bar close button hide the window, per Sergei’s explicit exception.

Place a short persistent hint beneath the desktop header: “Closing the window keeps Books Arranger running in the tray.” A one-time modal or toast is unnecessary: the visible hint explains the behavior without delaying close or stealing focus. Tray tooltip: “Books Arranger”. Left-click and “Open Books Arranger” show the existing window. Right-click menu: “Open Books Arranger”, separator, “Quit Books Arranger”. When quitting, replace Quit with disabled “Quitting…” and tooltip “Books Arranger — quitting after the current book” when a book is active, otherwise “Books Arranger — quitting”. Use a static recognizable books icon, with a contrasting silhouette at native tray sizes; no animation, color-only status or extra badge.

## One full Quit command

In desktop mode replace the browser’s “Stop server” action with “Quit Books Arranger”. Keep it quiet in the existing toolbar, with tooltip “Finish the current book and its cleanup, save pending work, then close the app.” It calls the same guarded full Quit path as the tray. The browser-only Stop server behavior remains outside this desktop spec. Do not leave the immediate server-stop command exposed in the desktop UI.

Idle Quit needs no confirmation. If a book is active, use a native Windows dialog: title “Quit Books Arranger”; message “Quit after the current book?”; detail ““<book title>” will finish, including its cleanup. Queued books stay saved for next time.” Buttons: “Quit after this book” and “Cancel”. Default focus is Cancel; Escape cancels; Enter activates the focused button. Cancel here only dismisses the unaccepted request. Display the book title as plain text, wrapping rather than truncating important identification. No force-quit or cancel-drain command is added.

Once Quit is accepted, insert a nonmodal status panel immediately below the header and above the existing content, in normal document flow. Heading: “Quitting after the current book” when active; body: ““<book title>” is finishing. No new books will start. Pending work is saved.” During cleanup show “Finishing cleanup before closing.” If no book is active show heading “Quitting Books Arranger”; body “Saving pending work and stopping background work.” Report actual phases; do not promise completion when cleanup fails or imply the 24-hour recovery copies are deleted. Retain the existing book progress below it.

Disable controls that start, pause, resume or change work, and review/queue/recovery mutations while draining. Keep viewing, filtering, scrolling and copying readable data available. Show one visible explanation “Controls are unavailable while Books Arranger closes.” Disable the desktop Quit button once accepted; repeated requests are idempotent. Maintain page focus; announce the heading and phase changes through a polite status region, without announcing every numerical progress tick. Title-bar close still hides to tray. A terminal refusal/error must display the actual supported recovery action; never claim a successful exit or bypass a hold.

## Startup errors

Use a native error dialog titled “Books Arranger could not start”, with a plain-language reason and one Close button. Known cases: catalog already open → “This catalog is already open in another Books Arranger window. Open that window or quit it before trying again.”; assigned port in use → “Books Arranger’s local connection is in use. Close the other Books Arranger instance, then try again.” Do not assert the competing process is Books Arranger when that is unproven; then say “The local connection is in use by another program.”; missing bundled runtime → “The installed app is missing required files. Reinstall Books Arranger using the installer.”; inaccessible data folder → “Books Arranger cannot open its data folder. Check that the drive is available and that you can access the folder.”

Unexpected errors: “The app could not start. Keep the error details below when reporting the problem.” Put technical diagnostics in a labeled expandable Details region only if the native dialog supports it; otherwise use the native detail field after the short reason, bounded to the relevant failure. No raw engine log as the primary message, no invented Retry button, no automatic catalog creation/migration as a response to an error. Close exits the failed shell; another healthy instance remains unaffected.

## Update notice (M2)

Use the existing approved update check, without adding processing or restart automation. Status copy: “Checking for updates…”; “Books Arranger is up to date (vX.Y.Z).”; “Could not check for updates. Try again later.” Show the last only in the update status area, without a startup modal. For download, “Downloading vX.Y.Z…” with actual determinate progress only when known. Failure: “Could not download the update. Your current version is still installed.”

When downloaded while busy, show a normal-flow notice: “vX.Y.Z is ready. Finish or pause active work before restarting to update.” Omit the restart action until the engine positively verifies all required idle conditions, including scanner, research, jobs and cleanup; an empty conversion slot alone is insufficient. Do not invent percent completion or a countdown. When idle, notice “vX.Y.Z is ready to install.” with “Restart to update” and tooltip “Save pending work, close Books Arranger and install vX.Y.Z. Processing stays paused after restart.” Tray item: “Restart to update to vX.Y.Z”. It uses the same idle-gated action. If work becomes active between rendering and click, refuse safely and refresh to the busy notice. Hide/disable update restart during accepted Quit. Install only after an explicit restart-to-update action; startup remains paused. Keep the notice visible until state changes; do not require a dismiss feature.

## First-run data folder selection

Authority: the M1 Brief already approves a selectable data folder outside the install folder and the default `%LOCALAPPDATA%\Books Arranger\data`. This selector chooses where the catalog is opened or explicitly created. It does not move a folder or rewrite stored paths/native identities. Existing users should select their current data folder in place so saved jobs, receipts and recovery remain associated with it. No additional product ruling is required for this selection flow.

Before starting an engine on an unconfigured first launch, show a setup panel titled “Choose a data folder”. Intro: “This folder stores your catalog, saved work and recovery copies. Your books stay in their library folders.” Two labeled choices in a native-style radio group: “Use an existing data folder” (initial selection) and “Create a new catalog”. Existing choice has a read-only, selectable path field, initially empty, and “Browse…” opening the native Windows folder picker. Helper: “Select the existing Books Arranger data folder. It will stay in its current location.” Primary action “Use this folder”, disabled until the selected folder passes the applicable existing-catalog checks. Secondary “Cancel”. Do not discover and silently adopt a checkout/data folder. A known path may be offered as a visibly labeled suggestion only if its origin is verifiable and the user still selects it explicitly; no required automatic suggestion.

For “Create a new catalog”, show the approved default path above, resolved to the actual folder, with “Browse…” to select another location. Helper: “A new catalog starts empty. To keep your saved queue and recovery records, use your existing data folder instead.” Primary action becomes “Create catalog”. This explicit action alone authorizes creation at the chosen eligible location; do not create the default catalog before the user confirms this mode and path. If the selected location already has a supported catalog, return to the existing-folder mode with “This folder already contains a Books Arranger catalog. Choose Use an existing data folder.” Do not replace its contents or overwrite its catalog. Unsupported/nonempty folders are refused unless the existing safe backend already positively establishes they are eligible; the selector does not introduce a broader overwrite or adoption policy.

Keep path text wrapped/selectable and visible at full length, with the picker alongside or below at narrow widths. Use the panel typography, padding, focus and button sizes defined below; mode options have at least 24×24px hit targets including their labels. Normal Tab order: mode choices, path/Browse, primary action, Cancel. Native folder-picker cancellation returns focus to Browse without changing the selection. Pressing Escape in the setup panel cancels setup; Cancel exits the unconfigured shell with no engine, no settings written and no catalog created. Until a catalog has actually started, the title-bar close also cancels setup; close-to-tray applies to the configured running app.

Validation messages appear directly below the path and are announced politely: “No Books Arranger catalog was found in this folder. Select your existing data folder or choose Create a new catalog.”; “This folder is unavailable. Check the drive and try again.”; “Books Arranger cannot access this folder. Choose a folder you can read and write.”; “This catalog is already open. Quit the other Books Arranger instance before opening it here.”; unrecognized/corrupt catalog: “This catalog could not be opened. Keep the folder unchanged and report the error details.” Do not claim all checks passed based only on a folder name or database filename. Show underlying bounded diagnostic details on failure, without rewriting receipts, deleting recovery, or falling back to an empty default catalog. A changed/disappeared folder between selection and start is rechecked by the guarded startup path.

On confirmation, display “Opening catalog…” or “Creating catalog…” according to the selected mode and disable repeated confirmation. Persist the chosen path only after guarded open/create succeeds; if that fails retain the selection for correction and preserve the prior saved setting. Refuse an install/resources folder or a protected source-library location under the existing native-directory safeguards: “Choose a data folder outside the app installation and your source libraries.” The backend’s stored identities and catalog lease remain authoritative. First launch shows the ordinary page with automatic processing Paused; no scan, queue resume, conversion or retirement starts because a folder was selected. Future launches reuse the explicitly saved path without showing setup. If it later becomes unavailable, present the actual startup error; never silently choose/create another catalog. Uninstall and update preserve the selected folder and its contents.

QA must verify both modes, picker cancellation, setup cancellation/close, long paths, unavailable/locked/corrupt/nonempty folders, failed confirmation preserving settings, first-launch Paused, and an existing private catalog opened in place with native identities/receipts unchanged. Measure mode-label, Browse, confirmation and Cancel rects in both modes and error states at minimum window size and 200% scaling. No actual installation or live catalog change is required by this UX specification.

## Layout, keyboard and themes

New notices use the existing panel surface, 16px padding, 16px separation, 15px system body text and 19px headings. Button minimum height 32px, minimum interactive target 24×24 CSS px, 10px toolbar gaps; wrap actions and long book/version/error text. No fixed-position notices overlaying controls. Native dialogs and tray menus follow the Windows light/dark theme. Existing web content uses its dark palette; new notices reuse it without introducing a separate theme switch. If Ender supports a light page variant, use the measured light palette below for these surfaces and check the whole page rather than mixing light notices into a dark page.

| Token | Existing dark | Light variant |
| --- | --- | --- |
| Surface | #1B2530 | #FFFFFF |
| Text | #EDF3F8 | #17212B |
| Muted text | #B8C6D5 | #465568 |
| Accent | #83BFFF | #165DA8 |
| Text on accent | #101923 | #FFFFFF |
| Border | #71869C | #687D92 |
| Warning/focus | #FFD58A | #765000 |

Measured using WCAG sRGB relative luminance (all pairs against Surface except button text against Accent): dark text 13.87:1, muted 8.92:1, accent 8.02:1, button 9.16:1, border 4.13:1, warning 11.18:1; light 16.29:1, 7.61:1, 6.63:1, 6.63:1, 4.25:1, 7.20:1 respectively. Text meets AA 4.5:1; boundaries/focus meet 3:1. Focus uses the existing 3px visible outline with 2px offset. State is always described in words as well as any icon/color.

Every new control is reachable in normal Tab order, works with Enter/Space, has an accessible name matching its visible label, and receives a concise tooltip. No global hotkeys or replacement of Ctrl+C/F/A; keyboard users can reach the tray through Windows notification-area navigation and activate the native context menu. Read-only status is not tab-focusable. Dialog focus is trapped only while the dialog is open and returns to the initiating control when cancelled. No focus stealing from background quit/update changes.

## Required implementation/QA evidence

Measure DOM bounding rectangles for the new status/update panels and controls at 950×650 and 1280×860, 100% and 200% scaling, long title/error text, every drain phase and update busy/idle/error state. Report overlapping rect pairs: none, except deliberate native dialogs. Verify wrap/reflow, visible focus, disabled-control explanations, screen-reader names/status announcements, theme contrast and native tray legibility in Windows light and dark modes. These are required acceptance checks, not claimed measurements of an unimplemented screen.

Packaged checks: title-bar close keeps processing alive; tray and in-window Quit share the drain path; pending books remain queued after relaunch; all owned shell/engine/media processes end after successful full Quit; duplicate/startup refusal leaves the original healthy instance intact; idle update cannot resume processing or bypass catalog/recovery protection. Existing M1 tests did not prove literal tray click/native confirmation or installer execution, so these need actual packaged evidence. First-run selection is covered above; data migration, signed installer claims and Google human-verification UI remain outside this spec. Route any newly required screen back to Judy before implementation.
