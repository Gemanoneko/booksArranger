## Navigation and layout

- Add **Manual Conversion** beside the existing library view at the top of the workspace. Keep the existing view as the initial tab and keep its current navigation, controls, and filters. Use a labelled tablist with one focusable tab at a time, arrow keys to move, Home/End for the first/last tab, and Enter/Space to select. Preserve the editor when switching tabs. After restart, saved drafts and queued work are available when reopening Manual Conversion.
- Reuse the existing panel, toolbar, path, field-help, focus and quiet button styles. Show **New book** and the saved manual drafts and pending jobs above the editor. Identify a row by its saved title or its source name and show its state, file count and destination when known. Selecting a row opens its editor or job details. Show the title and **View in Converted** for the active book when it completes, linking to its exact row in the existing Converted list. Keep the regular job controls and status there for work already queued.
- In the editor, use this reading order: **Source**, **Track order**, **Metadata**, **Export**, **Save draft**, **Queue conversion**. Put **Discard draft** next to Save draft with quiet styling. Place error/help text beside the relevant control and the persistent outcome line beside the actions. An empty editor starts with the two labelled source choices.

## Source and track order

- Use a **Folder** / **Files** radio group. **Folder** shows a labelled folder path field that accepts a pasted Windows path and **Browse…** to open the native folder picker. Commit the source selection on **Load folder** or a successful picker result. Caption: `Includes audio files directly in this folder.` **Files** shows **Choose files…** with the native multi-select audio picker, and uses the returned file paths as the explicit set. A cancelled picker leaves the selection intact. A new selection updates the editable list and takes effect in the saved draft when saved. Switching the source kind or selecting a new source preserves manually entered metadata and the current export choice. On a source change, remove obsolete match suggestions and request any new match against the current selection.
- Show the output order as a numbered list with each file's basename and a readable, wrapping full path when needed to distinguish tracks. Default to natural filename order (`2.mp3` before `10.mp3`). Reuse **Move up** / **Move down** with accessible names that identify the track, plus an **Include** checkbox for folder tracks or **Remove** for a file chosen individually. Show the included count and keep focus on the moved track, using the opposite move button or the row when the original control becomes disabled. Confirm one M4B will contain the included tracks in the order shown. An empty or invalid selection shows a cause by the source selector and the supported next step. New folder contents discovered after a draft was saved can be loaded for review and saved explicitly. Reopening a draft presents its saved set and order.

- Reuse the current field names and editing conventions for **Title**, **Author**, **Series**, **No.** (position in series), **Universe**, **Collection** and the existing short-story collection option where applicable. Show suggestions from the available metadata match in the editor, with the matched source identified in one line. Confident suggestions may pre-fill untouched fields. Preserve typed or explicitly cleared values, including during polling and after reopening. Show incomplete or uncertain fields for manual entry. A lookup pending or without a match leaves the editor available.
- **Save As…** opens the native save dialog with an app-suggested `.m4b` name when available. The user chooses the directory and exact filename. Display the chosen path as wrapping text in the editor and persist it with the draft. Retain it when the user cancels the dialog or edits metadata. If the output path is taken, display the actual conflict by the path and offer **Save As…** to choose another. Keep the selection and draft through picker or validation errors.
- By **Queue conversion**, show `The app verifies the exported audiobook before removing its included originals.` Present specific validation feedback for missing inputs, an unavailable destination, overlapping work or a changed source, with the next supported action. The user can save a draft while metadata or the destination is still incomplete once there is an eligible source selection.

## Persistent states

| State | What the user sees |
| --- | --- |
| Local changes | `Unsaved changes` beside the actions. After editing an existing draft, distinguish this from its still-active saved reservation. |
| Saving | `Saving draft…` until acknowledged. On confirmation, `Draft saved. {n} files reserved for manual conversion.` Preserve newer local edits if a reply for an older edit arrives. |
| Discard | Inline confirmation `Discard this draft and release its files for automatic processing?` with **Discard draft** and **Keep draft**. Clear the editor and show release only after confirmation from the app. |
| Conflict | Name the actual conflicting file and draft/job where available. Keep the editor and offer to open the conflicting draft or inspect the job if the app can link it. For in-flight work, show its state and tell the user when they can retry. |
| Queue requested | `Queuing conversion…` until accepted. Repeated presses and lost replies resolve against the same saved request. Show `Queued`, `Waiting for audiobook jobs to resume` or another precise queue state when acknowledged. |
| Queued or running | Show the persisted file count, title and destination. Use current audiobook job states for conversion, verification, and source cleanup, plus existing Pause/Resume controls and progress when available. Present the accepted plan as a read-only summary while that job owns it. |
| Source changed, failed or cleanup held | Keep the saved details. Show the failed stage and next supported action. Use existing Retry or cleanup actions where offered and let the user review changes to inputs or destination when the engine permits. A verified output with incomplete cleanup is reported as such. |
| Complete | `Converted` after verification and cleanup settle successfully. Offer **View in Converted**. Remove successfully handled files from overlapping jobs and keep unrelated source files available. |
